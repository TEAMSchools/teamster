    Cube MCP REST Coverage Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Make src/cube/mcp/server.py a complete read-only wrapper over the Cube REST API, with accurate descriptions and small default responses.

    Architecture: One file, server.py, keeps every tool. New tools reuse _request (auth, error, Continue wait polling). cubesql needs a streaming reader, so it gets one small private helper beside _request. Trimming is two pure functions, tested directly.

    Tech Stack: Python 3.13, mcp SDK 2.0 MCPServer, httpx, PyJWT, pytest.

    Spec: docs/superpowers/specs/2026-10-15-cube-mcp-rest-coverage-design.md

    All paths below are relative to the worktree /workspaces/teamster/.claude/worktrees/cbini/feat/claude-cube-mcp-rest-coverage. Run every command from there with uv run. Use git -C <worktree> for git.

    Global Constraints

    • Total tool wall-clock under 60 s; reuse TIMEOUT_SECONDS = 55.
    • stateless_http=True stays; no tool keeps state between calls.
    • Model guidance goes in tool docstrings, not instructions=.
    • Every query-object tool passes its query through _with_default_timezone.
    • No tool-side row limits. Cube's own limits apply.
    • canUseTransformedQuery is never read to build a default response.
    • No docstring names cube-* groups. Empty catalog / WHERE (1 = 0) causes: no dim_staff_cube_access row for the email, a none scope on that axis, or resolveAccess failing closed.
    • Gateway source of truth: src/cube/node_modules/@cubejs-backend/api-gateway 1.8.5 (dist/src/gateway.js, dist/src/query.js). Run npm ci in src/cube/ (main checkout) if it is missing.
    • Tests: uv run pytest tests/cube/test_mcp_server.py -v. Never bare pytest.
    • Live probes (tests/cube/test_zz_*.py): load the server with the real CUBE_REST_URL/CUBE_API_SECRET from the conftest secrets, set server.client = httpx.AsyncClient(base_url=server.CUBE_REST_URL, timeout=55) (the lifespan does not run under pytest), and set CUBE_USER_EMAIL to the user's email. If conftest does not supply the Cube secrets, stop and ask the user rather than skipping the probe.

    Endpoint facts (from gateway 1.8.5)

    Tool Request Response
    sql POST /sql {"query": <obj>} {"sql": {"sql": [str, list], "preAggregations": [...], "external": bool, ...}}
    sql (SQL input) POST /sql {"query": <str>, "format": "sql"} {"sql": <sql4sql result>}; needs sql scope (default scopes include it)
    dry_run POST /dry-run {"query": <obj>} {queryType, normalizedQueries, queryOrder, transformedQueries, pivotQuery}
    cubesql POST /cubesql {"query": <str>, "timezone", "throwContinueWait": true} chunked NDJSON: first line schema/lastRefreshTime/usedPreAggregations, then {"data": [...]} lines; an error line carries error
    convert_query POST /convert-query {"input": "sql", "output": "rest", "query": <str>} rest query object (from native rest4sql)
    graphql_to_json POST /graphql-to-json {"query": <str>, "variables": <obj>} {"jsonQuery": <obj>}; on a parse error Cube returns {"jsonQuery": null} with HTTP 200

    CUBE_REST_URL already ends in /cubejs-api/v1, so paths are /sql, not /v1/sql, matching the existing /load and /meta calls.

    Review Focus

    1. graphql_to_json gets {"jsonQuery": null} for a bad query: the tool must raise a clear error, not return null as if it worked. Test in Task 5.
    2. cubesql stream with an error line partway through (or as the only line): the tool raises with Cube's message, not a JSON decode error or a silent partial result. Test in Task 4.
    3. cubesql gets Continue wait on every attempt: the tool stops at the deadline with the same message shape load uses. Test in Task 4.
    4. sql response with no preAggregations key (a query no rollup covers): trimmed response has preAggregations: [], no KeyError. Test in Task 2.
    5. dry_run with a multi-query (compareDateRange) query: transformedQueries has several entries, and each one is summarized. Test in Task 3.

    Task 4: Add cubesql

    Files:

    • Modify: src/cube/mcp/server.py
    • Test: tests/cube/test_mcp_server.py

    Interfaces:

    • Produces: _parse_cubesql_stream(text: str) -> dict[str, Any]. Splits on newlines, skips blank lines, json.loads each. Returns {"schema": ..., "lastRefreshTime": ..., "usedPreAggregations": ..., "data": [<all rows, in order>]} (keys absent from the stream are omitted). Any line with an error key: return {"error": <that value>} and stop.
    • Produces: cubesql(ctx, query: str, timezone: str | None = None) -> dict[str, Any]. POST /cubesql with {"query": query, "timezone": timezone or DEFAULT_QUERY_TIMEZONE, "throwContinueWait": True}. Loop until the deadline: parse the body with _parse_cubesql_stream; if the result's error == "Continue wait", sleep 1 s and resend; any other error raises RuntimeError(f"Cube POST /cubesql: {error}"); else return.
    • Change: _request gains raw: bool = False. When raw, it returns response.text instead of response.json() and skips the Continue wait check. cubesql does its own polling on the parsed result. Keep the HTTP error branch for both.

    Read the whole response body (response.text). httpx buffers it; no streaming reader is needed, because the tool returns one object anyway.
