    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Fix the 9 bugs the fresh DDI run found, show only published worksheets and safe filter values, share explanations across a dashboard model, and add the formula check: a differing cell that still differs once every unmatched row is left out is a formula difference, whatever row causes it also holds.

    Architecture: Small fixes first, grouped by module. Then published sheets (read from the workbook XML), safe filter values and shared explanations. The formula check lives in a new formula.py: it builds, for each comparison, a dashboard-side and a Cube-side query over matched rows only (a rebuilt reconcile minus the saved unmatched keys), plus a self-check of each with nothing removed. sort prices them in the explanations' batch, runs them after the stored explanations, stores each comparison's result in its latest result, and recomposes run.json, so a checked cell is filed in <id>:formula by the same code that files cells with no group. Every failure leaves the cell closing by coverage, labelled "formulas not compared: ", and ask-owner lists it.

    Tech Stack: Python 3.13 via uv run, sqlglot, google-cloud-bigquery, pytest with DuckDB (--with duckdb).

    Decisions the spec left to the builder

    • Published (spec §3) is read from the workbook XML everywhere: a worksheet named by a <zone> of any <dashboard>, or whose <window class='worksheet'> is not hidden='true'. The second is exactly the set Tableau Server lists as views (tableau.expose_sheet's docstring: a hidden window publishes no view), so no command reads the Server views list, and read-sheet stays offline. rebuild-sheet records the result as rebuild_check.published; compare downloads the workbook only when that is not true or the workbook was republished since.
    • Grain column detection (Cube side): parse Cube's compiled row SQL with sqlglot; each grain member's projection (`<view>__<member>`) must be a bare column qualified by the alias of a FROM/JOIN table, all on one table. Which tables carry those columns comes from Warehouse.columns (table schema, a free metadata call, no query).
    • Fact reference rewrite: on the as-of-expanded Cube SQL, each `teamster-332318.<ds>.<t>` [AS `a`] FOR SYSTEM_TIME AS OF TIMESTAMP '…' of a table to filter becomes (SELECT * FROM `teamster-332318.<ds>.<t>` FOR SYSTEM_TIME AS OF TIMESTAMP '…' WHERE <key> IN (SELECT __key FROM __matched)) AS `a`. No alias, or no reference found, is "formulas not compared".
    • Matched keys: the reconcile's own joined CTE rebuilt in the query (reconcile._joined), keys of rows it files match with both sides present, minus the key of every other joined row, minus every saved unmatched key. A key is TO_JSON_STRING(STRUCT(...)) of reconcile._grain_keys; a NULL student is never matched; a time-dimension grain column is cast to DATE before keying on raw tables.
    • Self-check: the same rewritten query with the key predicate replaced by TRUE and, on the dashboard side, the original {rows} (no scope, reduce or cut restriction). It checks the wrapping reproduces the run's cell; it does not reference __matched. So 4 queries per comparison: each side matched and self-check, each one UNION ALL over the cuts holding checked cells, tagged __cut.
    • Where results live: a comparison's completed check goes in its latest result (data["formula_check"], with that result's fingerprint) and is honored by every later compose; sort recomposes run.json through compose_run, only when the run is still composed from the latest results. A stored check is reused while its fingerprint holds (no spend). A failure that stops the whole comparison is not stored, so the next sort retries it.
    • Formula item text: CellDiff.matched_only counts the cells the check filed. Local evidence names each such cell (cut, dims, both recomputed values); posted evidence carries masked counts only. Its row groups stay their own items ("still listed").
    • Labels: constants in formula.py (Task 12) and the refusals named in each task are the wording.
    • Stale or skipped comparisons get no formula check and no label: they are already listed as waiting.
    • Shared explanations key on dashboard_view, rows.grain and rows.values only; rows.dashboard_scope and rows.reduce may differ too, since {unmatched}'s columns do not depend on them.
    • Text measures are detected as a value field on a string column whose derivation is not a count; tableau._number says "text" only for a value with no digit, so 12K still reads as a number format.
    • * total rows skip only for dims on the rows or columns shelf; All keeps today's rule for every dim.
