    Apex Assessment Results Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Miami Apex (Focus) results flow through the shared assessment pipeline, so they appear wherever Illuminate results do, with no change to NJ numbers.

    Architecture: 2 source int_ models in the focus package (built in kippmiami) do all Apex-only logic: latest session, overall and per-standard scores, bands, and mastery. kipptaf reads them through sources-kippmiami.yml plus union_relations passthroughs. A source column (illuminate / apex) joins every assessment key in the kipptaf intermediates, which first get conformed column names. Apex rows then enter members → canonical → scaffold → rollup as a parallel branch, and every downstream consumer picks them up.

    Tech Stack: dbt (BigQuery), dbt unit tests, BigQuery MCP for verification, AppSheet, Google Sheets exposure.

    Spec: docs/superpowers/specs/2026-10-13-apex-assessment-results-design.md

    Global Constraints

    • Every NJ row in every changed model is identical before and after (count + key-plus-value fingerprint against prod). Illuminate surrogate keys in the marts do not move.
    • source values are exactly 'illuminate' and 'apex'. The marts carry it as assessment_type ('illuminate' / 'apex'), not as a source column.
    • The key for any assessment is (source, assessment_id); for a canonical group, (source, canonical_assessment_id). No join on either id alone.
    • Mastery: labels Level 3, Level 4, Level 5 → true; Level 1, Level 2, Low 1, Low 2, Mid 1, High 1, High 2 → false; any other label, or no band set → null. Never apply the is_default band set.
    • performance_band_label_number = 1..N by min_score within the band set.
    • Ignore stg_focus__apex_sessions.passed.
    • Session pick: latest completed_at among completed and not discarded and not excused sessions on non-deleted assignments, per student × assessment.
    • Overall: score_actual / score_max of the picked session. Standard: sum of responses with score_actual is not null, per standard (a response tagged to 2 standards counts for both). percent_correct 0–100, rounded to 1 place as in the rollup.
    • Apex branch filters academic_year >= 2026 (Focus syear).
    • Apex student_id = student_number.
    • Rename map (scope in the spec): powerschool_student_number → student_number; illuminate_subject_area → subject_area; illuminate_grade_level_id → grade_level_id; illuminate_academic_year → academic_year; rollup/scaffold grain illuminate_student_id → source + student_number (Illuminate id kept as a nullable passthrough). rpt_, mart, and Cube output column names never change.
    • Never run warehouse DDL/DML. Draft it; the user runs it.
    • Student-level Apex models: contains_pii: true (model level on passthroughs, column level on package models: student_number, scores, dates taken).
    • Run uv run dbt ... only; --project-dir an absolute worktree path.

    Review Focus

    1. Band set id collision. The rollup's final join to int_illuminate__performance_band_sets on performance_band_set_id would give Apex rows Illuminate bands where ids overlap. Apex rows must take band fields from int_focus__apex_results only (test in Task 7).
    2. Canonical id collision. 12 Apex ids equal Illuminate ids, so a canonical join on canonical_assessment_id alone merges them in assessments_canonical, score_anchors, resolved_section_enrollments, and the fact (test in Task 5).
    3. Ambiguous sections. A student in 2 core sections of a subject on the test date gets null section with section_match_method = 'multiple', not an arbitrary pick (test in Task 6).
    4. Untagged Apex assessment. No AppSheet row → null module/scope; it must still reach the rollup and the assessment dashboard, and not break regions_assessed_array unnests (test in Task 6).
    5. Mixed-subject assessment. Standards from 2 subject categories → null subject_area, not a fan-out (test in Task 1).
