    Validator: Saved Rows and Resume Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: run and triage survive a stop and pick up where they stopped, and triage reads each comparison's unmatched rows from a saved BigQuery table instead of rebuilding both sides per proof; plus the #6412 guard, the #6411 cell confirm, and a proof dry run in prove --check.

    Architecture: run compares one comparison at a time, as today. Each comparison returns its own slice of _Sides and saves its unmatched rows to one labelled table in teamster-332318.cube_validation_scratch with the same multi-statement query that returns the reconcile counts. run merges each slice and writes a checkpoint per comparison into the run folder, which decides what a resumed run skips. triage checks each table's labels, prices every proof up front, runs the proofs one at a time against the saved tables, and records each finished outcome in triage-progress.json. The session temp-table path is deleted. No threads: see the spec's Revision 2026-11-13.

    Tech Stack: Python 3.13 via uv run, google-cloud-bigquery, pytest with DuckDB (--with duckdb).

    Spec: docs/superpowers/specs/2026-11-13-validator-saved-rows-resume-design.md. Issues #6410 (main), #6411, #6412. PR #6402.

    Worktree: /workspaces/teamster/.claude/worktrees/cristinabaldor/fix/claude-validator-second-fact-time-dims (W below). Reach it by absolute path; use git -C W. Package: W/scripts/cube_validation/ (P below). Tests: W/tests/scripts/cube_validation/ (T below). Run tests from /workspaces/teamster with:

    uv run --project W --with duckdb pytest T/<file>::<test> -q

    Never bare pytest or python.

    Global Constraints

    • Scratch dataset: teamster-332318.cube_validation_scratch, location US, default table expiration 14 days, read and write for the Data Team group only. Named once, in saved.SCRATCH_DATASET.
    • The owner creates the dataset in their terminal. The implementer never runs DDL, DML or any warehouse, Cube or Tableau command outside Task 13.
    • The validator creates and replaces tables only inside the scratch dataset.
    • One saved table per comparison, with a bucket column holding value_differs, dims_differ, dashboard_only or cube_only.
    • Unmatched rows are student-level PII: they stay in BigQuery. Nothing new is written locally beyond what run writes today (checkpoints hold the same aggregates run.json holds).
    • No worker pools or threads: run compares one comparison at a time and triage runs one proof at a time (spec, Revision 2026-11-13).
    • Correctness over speed: time is a benchmark only. Never cut or loosen a check, guard or refusal to make something faster.
    • Resume on its own only when the last checkpoint is under 24 hours old; 24 hours to 7 days needs --resume or --restart; over 7 days refuses to resume. --moment overrides all three.
    • The run folder's checkpoint decides what run skips; table labels only guard triage (a mismatch refuses, never reads).
    • Every query counts against --max-usd and --max-usd-per-day through Warehouse. --max-usd caps each process; run.json's cost_usd is the total across processes.
    • Docstrings follow W/src/teamster/CLAUDE.md; comments follow .claude/rules/comments.md (no measurements, no history).
    • Commits: conventional commits, files staged by name, message ending with Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>. Each fix of the first three tasks is its own commit.

    2. A checkpoint under 24 hours old whose build has aged past time travel (the build start older than 7 days less the 1-hour margin). Expected: a refusal naming --restart, not a BigQuery error mid-run. Pinned in Task 9 (test_a_resume_past_time_travel_refuses_before_any_query).

    5. A table with the right name holding another run's rows (same view, moment and comparison, but a --fact-dataset dev run or an edited comparison). Expected: triage refuses that comparison's proofs. Pinned in Task 10 (test_a_proof_refuses_saved_rows_labelled_for_another_run).

    • _Sides (pipeline.py:712-732) also holds cube_tables and live, which the spec's checkpoint list omits. Both go in the checkpoint, or a resumed run's changed_dims (pipeline.py:1402) and live_sources differ. _Sides.clauses is never read or written; Task 7 deletes it.
    • The tables only the Cube side reads already come from Prepared.row_sides (sides.cube.tables - sides.dashboard.tables, confirm.py:1062), which triage rebuilds for its compile-only check anyway. The plan does not save them a second time.
    • frozen_sql's joined (confirm.py:711) differs from the reconcile's (compare.py:218): keys and per-side grain versus moved and cut flags. The saved table needs both, so the save query builds one joined with keys=True, moved=True and both sides' grain (__gc<i>, __gd<i>), since the side holding a row differs by bucket and the 2 sides can type a grain column differently.
    • cut_flags (pipeline.py:225-228) returns None when a cut caption is not a row column, which is why the DDI mastery-bucket-* cells cannot be sized. scope needs nothing: both row queries already apply it (pipeline.py:285-286, 336-338).
    • The DDI students-bucket-* comparisons measure count_students (a distinct count, decimals: 0), not a share; confirm._rebuilt sizes them as the mean of is_mastery. Task 2 adds a distinct-student count cell kind.
    • report.save_local names the folder after moment.end (report.py:412-416), so a re-run of a finished moment shares its folder. A run-state file marks a folder unfinished instead of the absence of run.json.
