    Leader Intent to Return Survey Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Assign the leader intent to return survey to recruitment's leader population, keep those leaders out of the staff intent to return survey and the general reminder feed, and give recruitment a follow-up Sheet of leaders who have not submitted.

    Architecture: One new domain model holds the leader rule. rpt_tableau__survey_links reads it for a new survey branch and to exclude leaders from the staff branch; completion and the Survey Dashboard pick the new branch up unchanged. A new Sheets extract reads the same model plus submissions.

    Tech Stack: dbt on BigQuery (kipptaf project), dbt unit tests, Google Sheets exposures.

    Spec: docs/superpowers/specs/2026-11-20-leader-intent-to-return-design.md

    Global Constraints

    • Survey title, everywhere it appears: Leader Intent to Return Survey (matches the form title and the reporting__terms name exactly).
    • Term code: LITR. Leader question shortname: litr_plans.
    • Job titles (22), departments (8), business units (5): exactly the lists in the spec's Recruitment's rules section. Managing Director of Talent Acquisition and the Talent Acquisition department are NOT in them.
    • Survey eligibility is the same expression as eligible_roster in models/extracts/tableau/rpt_tableau__survey_links.sql:70-74 (active, primary, rehire or hire at least 3 weeks before current_date()).
    • The reminder feed rpt_extracts__survey_reminder keeps one email column.
    • All work happens in the worktree /workspaces/teamster/.claude/worktrees/cristinabaldor/feat/claude-leader-intent-to-return; run every dbt command with uv run from src/dbt/kipptaf there. Before the first build, invoke the dbt-local-dev skill for dev-target and --defer usage.
    • Deploy before 2026-11-30.

    Setup values (owned by the user, outside code)

    Tasks 1 to 5 do not need these. Task 6 does. Ask the user for them when Task 6 starts if they are not already in the ledger.

    1. The leader form's responder URL (prefill form), after the form is created as a copy of the staff intent to return form, with the question text from recruitment's setup page minus the "LEADERS:" prefix. The copy must keep "collect verified email": completion resolves the respondent from their signed-in email.
    2. Confirmation that the reporting__terms row exists: 2026, name Leader Intent to Return Survey, code LITR, type SURVEY, 2026-11-30 to 2026-12-11.
    3. Confirmation that the form_items_extension sheet has a row for the leader question on the new form with abbreviation litr_plans.
    4. The follow-up Google Sheet URL.

    Review Focus

    • Non-leaders' staff intent to return assignments do not change: Task 2's before/after comparison against prod must return 0 rows each way.
    • The population matches the rule on today's roster (239 people on 2026-11-20: Newark 113, Camden 44, Miami 35, KTAF 29, Paterson 18, allowing for roster drift): Task 1 verification.
    • A KTAF leader in an Out department (for example Director, Teacher Development) and the MD of Talent Acquisition stay out: Task 1 unit test.
    • A leader with no manager on the roster still appears on the follow-up Sheet with blank manager columns: Task 4 unit test.
    • No placeholder link or URL reaches main: Task 6 grep.
