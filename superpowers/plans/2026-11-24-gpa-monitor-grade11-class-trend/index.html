    Cumulative GPA Monitor: end-of-11th-grade GPA by graduating class — Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Re-key the Trends pop-up's grade 11 chart (GPA - Splay over time) from school year to graduating class, one row per high school plus an "All high schools" total row, backed by 2 new dbt flags.

    Architecture: 2 boolean columns on rpt_tableau__gpa_cumulative_year (passed through rpt_tableau__gpa_goal_progress) carry the "last completed 11th-grade year" pick and the rolling 7-class window. The worksheet filters on them. The owner refreshes the data source in Desktop and republishes, a subagent rebuilds the worksheet through the tableau-workbook-xml skill and publishes a review copy, and Claude checks the render against a warehouse answer key before the owner publishes to production from Desktop.

    Tech Stack: dbt (BigQuery), dbt unit tests, Tableau Desktop, tableauserverclient via docs/tableau-xml/scripts/, Tableau MCP (read-only renders), BigQuery MCP.

    Execution: Tasks 1 to 3 run natively in this session. Task 4 waits on the owner. Task 5 is one subagent. Task 6 is this session plus the owner.

    Spec: docs/superpowers/specs/2026-11-24-gpa-monitor-grade11-class-trend-design.md (issue #6478)

    Worktree: /workspaces/teamster/.claude/worktrees/anthonygwalters/feat/claude-gpa-monitor-grade11-cohorts (abbreviated <wt> below). Every git call is git -C <wt>; every dbt call passes --project-dir <wt>/src/dbt/kipptaf.

    Who does what in Tableau, and why

    • The owner refreshes the data source in Desktop and republishes (Task 4). The 2 new columns reach the embedded extract only through that Refresh; hand-adding <metadata-record> entries has no tested pattern in the tableau-workbook-xml skill.
    • A subagent does the worksheet rebuild through that skill and publishes a review copy only (Task 5). A tableauserverclient publish drops embedded credentials (skill: What a publish drops), so a scripted production publish would break the scheduled refresh.
    • The owner opens the agent's .twbx in Desktop, the skill's only real check, and publishes to production from there with credentials embedded (Task 6).

    Global Constraints

    • Measure: cumulative_y1_gpa_unweighted; bands: gpa_band_label (3.5+, 3.0-3.49, 2.5-2.99, 2.0-2.49, below 2.0) with colors #001e62, #2f5fc4, #b6c0cf, #f9a21a, #d8342f.
    • Window: graduation_year between current_academic_year - 5 and current_academic_year + 1. Today (current_academic_year: 2026) that is the classes of 2021 to 2027.
    • Population: no new logic. The extract's existing filters (rn_year = 1, is_enrolled_recent, enroll_status in (0, 2, 3), not out of district, Newark and Camden) already mean "enrolled at the end of the year".
    • Each student counts once, at their last completed (non-is_projected) 11th grade year.
    • Worksheet name stays GPA - Splay over time, in the same place in the Trends container.
    • Total row on top, labelled All high schools. Columns labelled Class of YYYY. Above each bar ≥3.0: NN%; below each bar n=NNN.
    • Year logic lives in dbt. Tableau may read the flags but must not compute a window from dates.
    • Only the owner publishes to production.
    • PR body and commits carry no band-level counts (small cells); class totals only.

    Review Focus

    1. The total row disagrees with the school rows. Its n per class must equal the sum of the school rows' n, and its band shares must come from distinct students, not averaged school percentages. Checked in Task 6 against the answer key.
    2. Region parameter set to Newark or Camden. The total row must follow it (Camden shows only KHS, total equal to KHS). Checked in Task 6 by rendering with Region set each way.
    3. July rollover. The window must move with current_academic_year and nothing else. Pinned by the second unit test in Task 1.
    4. A current 11th grader whose graduation_year falls in the window. Their projected row must not count. Pinned by student 103 in the Task 1 unit test.
    5. The dashboard school filter. Picking a school elsewhere on the dashboard must not blank the other school rows. Checked in Task 6 by rendering with a school selected.

    • Step 4: Add the 2 columns to the model SQL

    Follow .claude/rules/dbt-sql.md S6 ordering. is_grade_11_trend_class is a simple function, placed before the existing is_latest_graded_year logical:

    -- current 12th graders (current_academic_year + 1) and the 6 classes before them
ifnull(
    e.graduation_year between {{ var("current_academic_year") }} - 5
    and {{ var("current_academic_year") }} + 1,
    false
) as is_grade_11_trend_class,

    is_last_completed_grade_11 contains a window, so it goes last, after the 2 case columns. The window runs after the model's where, so it only sees kept rows. false and null is false in BigQuery, so non-grade-11 rows never come out null:

    gcy.grade_level = 11
and not gcy.is_projected
and gcy.academic_year = max(
    if(gcy.grade_level = 11 and not gcy.is_projected, gcy.academic_year, null)
) over (partition by e.student_number) as is_last_completed_grade_11,
    • Step 5: Add the 2 columns to the properties file

    data_type: boolean, config.meta.contains_pii: true on both. Descriptions:

    • is_last_completed_grade_11: True on the student's latest grade 11 row that is not the current year's projection, among the rows this model keeps (the student was enrolled at the end of that year). A student who repeated 11th grade is true only on the later year; a student in 11th grade now is false on every row. The Cumulative GPA Monitor's by-class chart counts each student once on this row.

    • is_grade_11_trend_class: True when graduation_year is one of the current 12th graders' class (current_academic_year + 1) or the 6 classes before it. Moves forward each July with the current_academic_year variable. False when graduation_year is null.

    • Step 1: Write the answer-key query

    select
    graduation_year,
    coalesce(school, 'All high schools') as school,
    count(*) as n,
    round(100 * countif(gpa_band_label in ('3.5+', '3.0-3.49')) / count(*)) as pct_ge_3_0,
from `<dataset>.rpt_tableau__gpa_goal_progress`
where is_last_completed_grade_11 and is_grade_11_trend_class and gpa_band_label is not null
group by grouping sets ((graduation_year, school), (graduation_year))
