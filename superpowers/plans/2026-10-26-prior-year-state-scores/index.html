    Prior-Year State Scores Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Give prior-year state scores 1 home, as a benchmark_academic_year column on int_assessments__state_scores, and move its 3 consumers onto it with no value changes.

    Architecture: The new column records the school year a state score serves as a prior-year benchmark. Its value depends only on the test window. Each consumer keeps its own rule for which tests and subjects count. It drops its own year math and joins or filters on the column instead. int_assessments__fast_previous_year stops reading stg_fldoe__fast and base_powerschool__student_enrollments.

    Tech Stack: dbt (BigQuery), kipptaf project.

    Spec: the design decision comment on #5911 (https://github.com/TEAMSchools/teamster/issues/5911#issuecomment-6420614818).

    Global Constraints

    • The refactor preserves values. Every consumer column keeps its value and its data type. Any difference is a defect, unless it is listed and explained in the PR.
    • benchmark_academic_year rule:
    • academic_year + 1 for NJ administration_period = 'Spring', FL administration_period = 'PM3', and every FL assessment_name = 'EOC' row in any window.
    • academic_year for FL assessment_name = 'FAST' with administration_period = 'PM1'.
    • null otherwise (NJGPA Fall, FAST PM2).
    • The grade 8 NJSLA Algebra filter stays in int_assessments__goal_benchmarks only. Do not add it to the roster, and do not remove it. An Asana approval task tracks the decision.
    • The roster keeps its state student id join key. The existing /* TODO: find records that only match on SID */ stays.
    • int_assessments__state_scores has 10 consumers. Add the column. Do not rename or retype any existing column.
    • Run dbt through uv run. Run local builds per the dbt-local-dev skill: invoke it before the first build.

    Review Focus

    • FL EOC in a non-PM3 window gets academic_year + 1, not null. Prod has only PM3 EOC today, so only the unit test covers this case (Task 1).
    • scale_score is NUMERIC in int_assessments__state_scores and INT64 in stg_fldoe__fast. int_assessments__fast_previous_year must cast it back, or prev_pm3_scale and both scale_points_* columns change type in the payout roster (Task 4).
    • Percentile ranks move if any rank partition gains or loses a row. Compare ranks row by row, not just counts (Task 5).
    • The roster's left join must not fan out once it reads the long table directly. Its on filters must narrow to NJSLA plus FAST PM3 with a non-null scale score, as the CTE did (Task 3).
    • The 8 FAST PM3 rows with no student_number must stay out of int_assessments__fast_previous_year. Joining on fleid to state_student_id keeps them out today (Task 4).
