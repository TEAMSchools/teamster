    DDI Suite student dimensions in Cube: implementation plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Put every DDI Suite student dimension still missing from student_assessment_scores_view into the marts and Cube: the school week, 3 per-student flags, the homeroom name and section number, and 3 subject-picked flags.

    Architecture: All new dbt columns land on dim_student_enrollment_status (1 row per enrollment stint), copied from the extract models the DDI Suite reads today, joined on student_enrollment_key. Cube exposes them through the existing student_enrollment_status cube; the 3 per-subject members live on the student_assessment_scores cube next to #6305's bucket and pick the ELA or math column by bucket_subject.

    Tech Stack: dbt (kipptaf, BigQuery), dbt unit tests, Cube YAML, tests/cube/test_cube_schema.py (pytest + Cube compile), BigQuery MCP for acceptance queries.

    Spec: docs/superpowers/specs/2026-11-11-ddi-suite-student-dimensions-design.md

    Global Constraints

    • Worktree <wt> = /workspaces/teamster/.claude/worktrees/cristinabaldor/feat/claude-ddi-student-flags. Use git -C <wt> and absolute <wt>/... paths; run dbt and pytest through uv run. Invoke the dbt-local-dev skill before the first dbt build.
    • Copy the dashboard: every value equals what the extract model holds for that stint today. No "as of assessment date" logic, no coalescing beyond what the extract already does.
    • New dbt columns are column-level config.meta.contains_pii: true, with a description: and data_type. The model is contract-enforced.
    • dbt column names (final): is_sipps, is_tutoring, is_self_contained, homeroom_name, homeroom_section_number, is_ela_low_25, is_math_low_25, ela_state_test_proficiency, math_state_test_proficiency, dibels_most_recent_composite.
    • View member names (final): the 5 per-student names above, plus is_low_25, state_test_proficiency, dibels_most_recent_composite, school_week_start_date, school_week_end_date.
    • The ELA/math pair members on the student_enrollment_status cube are public: false. No member goes on any view other than student_assessment_scores_view. No member joins the proficiency_rollup pre-aggregation.
    • One-column Cube members get a description identical to their dbt column and a TWINS entry in tests/cube/test_cube_schema.py.
    • No student value (name, number, id, row) in a commit message, PR body or issue comment.

    Commands, referred to below by name:

    • DEV BUILD <selection>: uv run dbt build --project-dir <wt>/src/dbt/kipptaf --target dev --defer --favor-state --state /workspaces/teamster/src/dbt/kipptaf/target/prod --select <selection> 2>&1 | tail -n 30
    • UNIT <model>: the same flags with dbt test and --select "test_type:unit,<model>".
    • CUBE TESTS: cd <wt> && uv run pytest tests/cube/ -q 2>&1 | tail -n 20. Run npm ci in <wt>/src/cube once first; check the summary shows no skipped compile test.
    • LINT <files>: from <wt>, /workspaces/teamster/.trunk/tools/trunk check --force --no-fix <files> </dev/null.

    Review Focus

    1. A student_number that repeats in 2 regions must take only its own region's flags. The key includes _dbt_source_project; Task 2's unit test pins it with a same-number row in another region.
    2. A student with 2 stints in 1 year gets each stint's own extract values and no extra rows. Task 2's unit test pins it; the dim's unique PK test backs it.
    3. Miami is_self_contained stays null (the extract's value), not false. Task 2's unit test pins it.
    4. A Math assessment shows No Composite Score Available for DIBELS, and a science assessment shows null for all 3 subject members. Task 5 pins both with a compiled-SQL check.
    5. A stint with no extract row (for example a grade 99 placeholder) gets null flags, not a dropped dim row. Task 2's and Task 4's unit tests pin it.
