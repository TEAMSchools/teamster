    DDI Module Goal Rules Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Move every goal value the DDI Suite workbook hard-codes into the goals lookup, so its 3 goal calculations read data instead of literals.

    Architecture: A new "Module Goal Rules" tab on the Assessments sheet holds the ET, CRQ and TP rules. A new domain intermediate expands each rule to the Illuminate subject areas of its discipline. rpt_tableau__ddi_dashboard keeps grade_goal, school_goal and region_goal raw and adds 3 *_goal_differentiated columns that apply the QA goal (PR #6357) and the rules. After merge, the workbook's 3 goal calculations point at the new columns.

    Tech Stack: Google Sheets (Sheets connector), dbt on BigQuery (kipptaf), Tableau .twb XML (tableau-workbook-xml skill).

    Spec: No separate spec. Issue #6117 plus the decisions below, made on 2026-11-11 and 2026-11-12 in the session that wrote this plan.

    Decisions

    1. Everything ships in PR #6357 (draft), branch anthonygwalters/feat/claude-k2-qa-goal-column, worktree /workspaces/teamster/.claude/worktrees/anthonygwalters/feat/claude-k2-qa-goal-column. The PR keeps Refs #6117.
    2. The ET, CRQ and TP rules live on a new "Module Goal Rules" tab, one row per region, module type, discipline and grade range.
    3. The view adds grade_goal_differentiated, school_goal_differentiated and region_goal_differentiated. The raw goal columns go back to the plain lookup values, which moves #6357's QA override into the new columns. The live workbook ignores the new columns until its calculations switch, so no goal is double-counted between merge and republish.
    4. Grade 9 ET keeps today's behavior: no rule, so the plain lookup goal. It is an open question for T&L (see the end of this plan).
    5. The workbook edit deletes the 7 unused goal parameters and leaves the i-Ready 80% lesson goal on O3 - i-Ready as it is.

    Global Constraints

    • Rule values come from the production DDI Suite (luid 6d82b643-59a8-4106-b2f9-97ddf7f638e7, updated 2026-11-11 23:42 UTC):
    • ET: 0.80 for NJ ELA, grades 0-8.
    • ET: 0.80 for NJ, any subject, grades 10-12.
    • CRQ: lookup goal + 0.10 for NJ Math, grades 1-8.
    • TP: lookup goal + 0.10 for NJ ELA, Math and Science, grades 3-12.
    • NJ means region in Newark, Camden, Paterson. Miami rows get differentiated goals equal to the raw goals.
    • Precedence, highest first: a fixed rule goal, then the QA goal on QA and CRQ modules, then a rule offset added to the raw goal, then the raw goal.
    • A rule row with a blank discipline applies to every subject.
    • Disciplines come from Illuminate_Subject_Area → Discipline in stg_google_sheets__assessments__course_subject_crosswalk.
    • A Sheets named range must cover whole columns. The connector saves it bounded to the grid's rows, so the user resets it in the Sheets UI.
    • Shared staging writes (--target staging) go to the user's terminal; the auto-mode classifier blocks them.
    • A production workbook publish needs the user's 2 typed confirmations (tableau-workbook-xml step 6).

    Review Focus

    1. K-2 CRQ Math, grades 1-2: expect the QA goal, not QA goal + 0.10. The CRQ rule covers grades 1-8, so precedence alone keeps the QA goal. Pinned in the Task 4 oracle query.
    2. A row with no lookup goal row (for example an HS subject the Academic Goals tab lacks): ET still shows 0.80, because a fixed goal does not need the raw goal. Pinned in the Task 4 oracle query.
    3. A subject the crosswalk does not map (Dance, Physical Education): only the blank-discipline ET rule for grades 10-12 applies. Pinned in the Task 3 unit test and the Task 4 oracle query.
    4. A subject the crosswalk maps to 2 disciplines would match 2 rules and fan out the view. The Task 3 uniqueness test and the view's grain test both fail at error.
    5. Crosswalk disciplines are wider than the workbook's [Discipline] group: 11 subjects (Algebra II Honors, Algebra IIA, Algebra IIB, AP Calculus, AP Calculus AB, AP Statistics, Pre-Calculus, AP Literature, Composition 100, Composition 200, Composition 300, Writing) map to Math or ELA in the crosswalk and to Other in the workbook. On 2026-11-12 they had 0 NJ ET, CRQ or TP rows, so the oracle query expects no difference; a difference on one of them is a behavior change to report, not a bug.

    • Step 5: Run the oracle query. It rebuilds the workbook's current formula in SQL from the dev view's raw goals and compares it to the dev differentiated columns. Expected: 0 rows.
    with
    d as (
        select
            region, grade_level, module_type, subject_area,
            grade_goal, school_goal, region_goal,
            grade_goal_differentiated, school_goal_differentiated,
            region_goal_differentiated,
            region in ('Newark', 'Camden', 'Paterson') as is_nj,
            case
                when subject_area in ('AP Language', 'English 100', 'English 200', 'English 300', 'English 400', 'Text Study') then 'ELA'
                when subject_area in ('Algebra I', 'Algebra I MS', 'Algebra II', 'AP Pre Calculus', 'Geometry', 'Geometry Honors', 'Math 4', 'Mathematics') then 'Math'
                when subject_area in ('Biology', 'Chemistry', 'Human Anatomy and Physiology', 'Physics', 'Science') then 'Science'
                else 'Other'
            end as discipline,
        from `teamster-332318.zz_anthonygwalters_kipptaf_tableau.rpt_tableau__ddi_dashboard`
        where student_number is not null
    ),
    qa as (
        select * from unnest([
            struct('Newark' as region, 0 as grade_level, 'ELA' as discipline, 0.78 as goal),
            ('Newark', 1, 'ELA', 0.63), ('Newark', 2, 'ELA', 0.76),
            ('Newark', 0, 'Math', 0.90), ('Newark', 1, 'Math', 0.79), ('Newark', 2, 'Math', 0.71),
            ('Camden', 0, 'ELA', 0.61), ('Camden', 1, 'ELA', 0.63), ('Camden', 2, 'ELA', 0.76),
            ('Camden', 0, 'Math', 0.83), ('Camden', 1, 'Math', 0.77), ('Camden', 2, 'Math', 0.53),
            ('Paterson', 0, 'ELA', 0.78), ('Paterson', 1, 'ELA', 0.50), ('Paterson', 2, 'ELA', 0.64),
            ('Paterson', 0, 'Math', 0.90), ('Paterson', 1, 'Math', 0.78), ('Paterson', 2, 'Math', 0.79)
        ])
    ),
    expected as (
        select
            d.*,
            case
                when is_nj and d.grade_level < 9 and d.discipline = 'ELA' and module_type = 'ET' then 'fixed'
                when is_nj and d.grade_level > 9 and module_type = 'ET' then 'fixed'
                when is_nj and d.grade_level <= 2 and d.discipline in ('ELA', 'Math') and module_type in ('QA', 'CRQ') then 'qa'
                when is_nj and d.grade_level between 1 and 8 and d.discipline = 'Math' and module_type = 'CRQ' then 'offset'
                when is_nj and d.grade_level > 2 and d.discipline in ('ELA', 'Math', 'Science') and module_type = 'TP' then 'offset'
                else 'raw'
            end as branch,
            qa.goal as qa_goal,
        from d
        left join qa
            on d.region = qa.region
            and d.grade_level = qa.grade_level
            and d.discipline = qa.discipline
    )
select region, grade_level, module_type, subject_area, branch, count(*) as n_rows,
from expected
where (
    case branch
        when 'fixed' then grade_goal_differentiated = 0.8 and school_goal_differentiated = 0.8 and region_goal_differentiated = 0.8
        when 'qa' then grade_goal_differentiated = qa_goal and school_goal_differentiated = qa_goal and region_goal_differentiated = qa_goal
        when 'offset' then abs(grade_goal_differentiated - (grade_goal + 0.1)) < 1e-9 and abs(school_goal_differentiated - (school_goal + 0.1)) < 1e-9 and abs(region_goal_differentiated - (region_goal + 0.1)) < 1e-9
        else grade_goal_differentiated is not distinct from grade_goal and school_goal_differentiated is not distinct from school_goal and region_goal_differentiated is not distinct from region_goal
    end
) is not true
group by region, grade_level, module_type, subject_area, branch
order by n_rows desc

    is not true counts a null comparison as a mismatch. A null raw goal under offset gives a null comparison, and the workbook also shows null there, so check any offset row the query returns for a null raw goal before treating it as a defect.
