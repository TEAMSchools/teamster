    Non-Tableau rpt_ error tests Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Every test on a kipptaf rpt_ model under models/extracts/ (outside tableau/) runs at error, backed by upstream warn tests and defenses for the 5 that fail in prod today.

    Architecture: One extracts: +severity: error folder block replaces the tableau: block. The 5 prod failures are source-data defects. Each one gets a warn on the earliest model that sees it, plus a defense in an allowed layer. Then its rpt_ test can run at error.

    Tech Stack: dbt (BigQuery), kipptaf project plus the finalsite source package.

    Spec: none. Rulings settled in conversation and recorded below; #5948 is the tracking issue (Refs #5948, no new issue). PR 5 precedent: docs/superpowers/plans/2026-10-16-tableau-rpt-error-tests.md.

    Global Constraints

    • Rule: .claude/rules/dbt-yaml.md Test config defaults. A source-data defect gets a warn on the earliest model that sees it, with a description naming the source system, what is wrong, and what to change there.
    • A5: a dedupe or pick lives only in stg_ or a source int_.
    • An error test lands only after its query returns 0 rows in prod.
    • finalsite is a source package: its tests default to error, so every new warn there sets config: severity: warn explicitly.
    • Prod-deferred flags: --target dev --defer --favor-state --state /workspaces/teamster/src/dbt/kipptaf/target/prod.
    • Always uv run dbt. Stage with git add -u (plus git add <new file>).

    Rulings (decided with the user)

    1. One extracts: +severity: error block replaces extracts: tableau:. The int_ tests under extracts/ that resolve to warn today are pinned to warn.
    2. The 7 ParentSquare file-to-file relationships tests and the 2 ParentSquare and 3 Clever "resolves"-style singular tests stay. They are a recorded exception for outbound-feed integrity, named in one line in dbt-yaml.md.
    3. accepted_values: keep a test when the model's logic produces the values. Move it upstream when the values come from upstream.
    4. The 4 csgf_hs_enrollment Y/N tests stay. The model's if() and coalesce() produce them.
    5. The kippfwd_miami_roster.iep_status test moves to int_extracts__student_enrollments.iep_status at error. That model produces the label, and prod holds only Has IEP and No IEP. The rpt_ not_null goes too, because a coalesce makes the column non-null by construction.
    6. The Ignite course_grade A-F test is deleted. PowerSchool letter grades legitimately include other codes. The model's case maps anything outside A-D to not passing, so an upstream warn would fire on valid data.
    7. The 5 prod failures get these defenses:
    8. Coupa duplicate active addresses: flag the newest active id per name in stg_coupa__addresses, and join on that flag. Ops (Greg Giles) confirmed both addresses are active on purpose while buildings move. The fix in Coupa is to rename the old building's address.
    9. More than 1 matriculated application: use the existing base_kippadb__application.rn_app_enr pick, as rpt_tableau__kfwd_dashboard does. Anthony Walters is confirming the rule (Asana task 1219594691444482).
    10. DeansList Relationship null (Finalsite emergency contacts): fill Unknown.
    11. Focus emergency contact with no last name: drop the row, matching the existing blank-first-name filter.
    12. Delete test_kippfwd_miami_roster_current_year_not_empty. It tests build timing (data presence), not a regression.
    13. Grain backfill for rpt_ models with no grain test goes to a follow-up PR.

    Review Focus

    • A Coupa address name with an active and an inactive row: the flag must land on the active one, even when the inactive row has the higher id.
    • A student with 1 transfer and 1 non-transfer matriculated application: the CSGF join must keep only the non-transfer one.
    • An emergency contact with a first name and an empty-string (not NULL) last name: it must be dropped like a NULL.
    • An int_ test under extracts/ that resolves to warn today and has no explicit severity: the folder block must not flip it.
    • A test whose warn override is removed: it must still pass in prod.

    Task 1: Coupa address dedupe

    Files:

    • Modify: src/dbt/kipptaf/models/coupa/api/staging/stg_coupa__addresses.sql
    • Modify: src/dbt/kipptaf/models/coupa/api/staging/properties/stg_coupa__addresses.yml
    • Modify: src/dbt/kipptaf/models/extracts/coupa/rpt_coupa__users.sql
    • Modify: src/dbt/kipptaf/models/extracts/coupa/properties/rpt_coupa__users.yml

    No kipptaf source carries a data test, so the early warn goes on the staging model. Staging keeps every row and flags the pick (is_current_for_name), so that warn still sees the duplicates.

    • Step 1: In stg_coupa__addresses.yml: - Add unique on id (severity: error). - Add unique on name with config: {where: active, severity: warn}. Its description says 2 active Coupa addresses share a name, usually during a building move, and the fix is to rename the old building's address in Coupa. - Add unique on name with config: {where: is_current_for_name, severity: error}.
    • Step 2: Run uv run dbt build --select stg_coupa__addresses <prod-deferred flags>. Expected: the build fails because is_current_for_name does not exist.
    • Step 3: In stg_coupa__addresses.sql, add is_current_for_name (bool). It is true for the active row with the highest id per name, and false for every other row: a row_number() partitioned by name over active rows, ordered by id desc, then active and rn = 1 in the next CTE. Add model and column descriptions to the yml. The column description states the newest-id rule.
    • Step 4: Re-run Step 2. Expected: the active-name warn WARNs on 3 names. The is_current_for_name unique passes.
    • Step 5: In rpt_coupa__users.sql, change the address join and a.active to and a.is_current_for_name. In rpt_coupa__users.yml, remove severity: warn and the TODO(#4409) comments from both unique tests and set severity: error. Run uv run dbt build --select rpt_coupa__users <prod-deferred flags>. Expected: both unique tests PASS.
    • Step 6: Commit: fix(coupa): send one default address per user to Coupa.
