    Validator: Coverage and Known Gaps Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Cut the validator's unused steps (check-api, anchors and identities, cell sizing, prove --check), close differing cells by coverage with a formula-difference outcome, give run its own pre-spend checks, a comparison subset, progress lines and per-comparison latest results, close #6346, #6343 and

    6181 items 1, 7, 8, 12 and 14, rename the commands and keys, and update the

    skills.

    Architecture: Removals first, so new code is written against what stays. A row group carries its per-cut row counts on each side (Group.cut_rows), and a new coverage.py places each group's rows in a cell exactly: a cell closes when every group with a row in it is in cause or decided, and a differing cell no group has a row in becomes a formula difference (<id>:formula, decided with formula: true). run (renamed compare) plans every comparison's queries, checks the workbook and prices them all before the first billed query, then compares the chosen comparisons and writes each one's result to <cache>/<view>/latest/<id>.json; run.json is composed from those results, each at its own moment. Old command and key names are refused with the new name.

    Tech Stack: Python 3.13 via uv run, google-cloud-bigquery, tableauserverclient, sqlglot, pytest with DuckDB (--with duckdb).

    Spec: docs/superpowers/specs/2026-11-14-validator-coverage-and-gaps-design.md (the authority). Context: docs/superpowers/specs/2026-11-13-validator-saved-rows-resume-design.md and its plan (Tasks 1-12 done; its Task 13 is superseded). Issues #6410 (main),

    6346, #6343, #6181. PR #6402.

    Worktree: /workspaces/teamster/.claude/worktrees/cristinabaldor/fix/claude-validator-second-fact-time-dims (W below). Package: W/scripts/cube_validation/ (P). Tests: W/tests/scripts/cube_validation/ (T). Run every test from W:

    uv run --with duckdb pytest tests/scripts/cube_validation/<file>::<test> -q

    Baseline before Task 1: uv run --with duckdb pytest tests/scripts/cube_validation/ -q → 1198 passed. Every task ends with the whole suite green (the count moves as tests are deleted and added; no failures, no new skips).

    Global Constraints

    • One PR, #6402. Offline tests only; the implementer runs no warehouse, Cube or Tableau command. Live use goes through the cube-validation skill's runner, each spend approved by the owner.
    • No parallel workers in run (compare) or triage (sort): one comparison and one explanation at a time. The new up-front price dry-runs one query at a time too.
    • No student or staff value in any output a task adds that can reach GitHub: the formula item, progress lines, the trace's model chain, the #6346 labels. Counts under 10 are masked with report.mask / report.shown_counts wherever the text is posted (evidence_posted, review issue, decision YAML).
    • Correctness over speed: never cut or loosen a check, guard or refusal to make a step faster.
    • Coverage closes a cell only on proven or decided rows; a cell with an unproven row stays in investigate. A formula difference never closes without the owner seeing it (it is its own item and decision).
    • An old validation file is refused, never silently read: anchors:, identities:, rows.cell, a cells: decision, and every key renamed in Task 12, each with a message naming the key and what to do.
    • Old command and key names are refused with the new name; no aliases.
    • Docstrings follow W/src/teamster/CLAUDE.md; comments follow .claude/rules/comments.md (no measurements, no history).
    • Commits: stage each file by name (never -A, -u or .), conventional commit subject, body Refs #6410 (Task 9: Refs #6346; Task 11: Refs #6343; Tasks 10 and 13 add Refs #6181), last line Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>. Write the message to <session scratchpad>/commit-msg-<slug>.txt and git commit -F it if a hook blocks -m.
    • Markdown edits (Task 14) are linted with /workspaces/teamster/.trunk/tools/trunk check --force --no-fix <files> </dev/null from W.

    Review Focus

    1. A differing cell whose dim is part of the row grain (or whose comparison has no rows): groups cannot be placed in it, so it must stay open with a reason, never cover or read as a formula difference. Pinned in Task 5 (test_a_cell_on_a_grain_dim_stays_open_and_says_why) and Task 6 (test_an_unplaceable_cell_is_never_a_formula_difference).
    2. A group whose rows sit in the same dims under another cut only: it has no row in this cut's cell, so it neither covers the cell nor keeps it from being a formula difference. Pinned in Task 5 (test_a_group_with_no_rows_under_the_cell_cut_does_not_cover_it).
    3. A composed run.json whose comparisons ran at different moments: an explanation, a trace or a hand check must read each comparison's own saved table and moment, never the newest. Pinned in Task 8 (test_an_explanation_reads_its_own_comparison_s_moment).
    4. A stale check that flags changed data, or misses a Cube or dbt view definition change. Expected: SQL or entry changes are stale, a new build alone is not. Pinned in Task 8 (test_a_new_build_alone_is_not_stale, test_a_changed_view_definition_is_stale).
    5. A formula: true decision after a cell gains an unproven row: that cell leaves the formula item for the cells item; the decision keeps covering the rest. Pinned in Task 6 (test_a_cell_that_gains_a_row_leaves_the_formula_claim).

    Findings from the code that shape the plan

    • compare._outer_sql already returns per group and cut each side's row count (__s_k<j>_c_rows, __s_k<j>_d_rows); cut_flags always yields at least one cut for a comparison with rows (_cuts returns [{}]). So every group can carry exact per-cut counts. The value-column n/sum stats and the count_students branch exist only for sizing.
    • link_cells reads triage._entries(run), which lists only open groups. A group a group: decision closed sits in run.applied.quiet; a group a cause decision decides stays open with decided marked. Coverage must read both.
    • decisions.apply closes a comparison's CellDiff with a cells: true decision; CellDiff is one per comparison. Splitting it by kind (cells, formula) keeps open_cells / quiet_cells and their JSON.
    • triage's explanation runner (confirm.run_stored) already dry-runs every explanation it will run before running any and records a dry-run failure as "not run". That covers what confirm.check_proofs did for prove --check, so check_proofs and pipeline.current_row_sides are deleted, not moved.
    • pipeline._compare_one builds and runs each query in turn. Pricing every query first needs a plan/execute split; the metadata lookups that decide which queries exist (fact_builds, network_schools, changed_between) run before the price, as today.
    • bq.Warehouse.script runs the save script as one job; a temp table's reads cannot be dry-run before it exists. pipeline.inline_unmatched (the same join as one SELECT) prices the scan that dominates it.
    • run.moment is read by confirm.require_saved, proof_sql, run_proof, trace (build=run.moment), triage.value_check, answers (expiry, moment) and report. Per-comparison moments go through RunResult.moment_of(comparison_id).
    • pipeline.run and compare.py share a name space (from . import compare), so the Python function keeps the name run; renames are user-facing (CLI, YAML keys, folder, messages, JSON keys the skills read), not module or function names.
    • trace._Bucket.children already skips a model it cannot read; what stops a whole bucket is a failed level query (runner.level → None) or a failed dry run (Stopped), both of which can come from one model among several frames.
    • #6181 items 7 and 8 (comments on the issue) are run --comparison and progress output; items 12 and 14 are the tableau fixes.
