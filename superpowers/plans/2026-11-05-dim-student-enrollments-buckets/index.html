    ELA and math buckets in the marts: implementation plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Put each student's ELA and math bucket on dim_student_enrollments, Miami's archived buckets in int_students__bucket_assignments, and a bucket_subject on dim_assessments, so the next PR can expose a subject-matched bucket in Cube.

    Architecture: The Miami PowerSchool archive joins the kipptaf int_powerschool__spenrollments union. The bucket model resolves Miami archive studentids through int_powerschool__ada. The enrollment dimension joins the bucket model once per subject and applies the 2025 rule. Internal assessments get bucket_subject from the course subject crosswalk in int_assessments__assessments_members; other families map it in their dim_assessments branch. This is the type 3 (dbt) PR; Cube follows in a separate branch that refs #6192.

    Tech Stack: dbt (kipptaf project, BigQuery), dbt unit tests, BigQuery MCP for acceptance queries.

    Spec: docs/superpowers/specs/2026-10-26-dim-student-enrollments-buckets-design.md, including its "Revision 2026-10-29" section.

    Global Constraints

    • The rule, per column: academic_year >= 2025 with a stored bucket gives the stored bucket; academic_year >= 2025 with none gives Bucket 4; academic_year < 2025 gives null; grade_level = 99 gives null.
    • Column names ela_bucket and math_bucket, data_type: string, column-level config.meta.contains_pii: true.
    • One value per enrollment row; the bucket model's latest-assignment pick decides the value. No key or hash changes on any mart.
    • bucket_subject values: Reading, Math, or null.
    • The Miami archive branch (academic years 2024 and 2025) and the Focus branch (2026 on) must not overlap on academic_year; the bucket model's grain test catches an overlap.
    • Out of scope: the nj_student_tier rule in int_extracts__student_enrollments_subjects, every Cube file, and NJ Tutoring.
    • Worktree <wt> = /workspaces/teamster/.claude/worktrees/anthonygwalters/feat/claude-dim-student-enrollments-buckets. Run every command from /workspaces/teamster with absolute <wt> paths, dbt through uv run, and --state /workspaces/teamster/src/dbt/kipptaf/target/prod.
    • No student value (name, number, id, row) in a commit message or the PR body.

    Dev build command, referred to below as DEV BUILD <selection>:

    uv run dbt build --project-dir <wt>/src/dbt/kipptaf --target dev --defer \
  --favor-state --state /workspaces/teamster/src/dbt/kipptaf/target/prod \
  --select <selection> 2>&1 | tail -n 30

    Unit-test command, UNIT <model>: the same flags with dbt test and --select "test_type:unit,<model>".

    Review Focus

    1. A Miami archive studentid with no int_powerschool__ada row drops its bucket silently. Task 2 pins it with a unit-test row and an acceptance query that every archived bucket student reaches the model.
    2. A student_number that repeats in 2 regions must take only its own region's bucket. Task 3 pins it with a unit-test row.
    3. A student with 2 enrollment stints in 1 year gets the same bucket on both rows and no extra rows. Task 3 pins it with a unit-test row; the dimension's unique key test backs it.
    4. An assessment subject with no crosswalk row (Word Work), or with a trailing space (AP Calculus), gets a null bucket_subject, as the dashboards give it no tier. Task 4 pins the no-row case with a unit-test row.
    5. A crosswalk subject that maps to 2 disciplines would fan out the members model. The members grain test and the dim_assessments unique key test catch it; Task 4 runs both.

            if(specprog_name like '%ELA', 'Reading', 'Math') as `subject`,

        group by 1, 2
