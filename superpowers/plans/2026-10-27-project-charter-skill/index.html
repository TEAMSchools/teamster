    Project Charter Skill Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: A project-charter skill that turns a stakeholder ask into an intake brief, a filled Project Management Templates doc, a dated work plan, and an Asana project, with a review stop after each.

    Architecture: One skill under .claude/skills/project-charter/. SKILL.md carries the size test, the four phases and their stop points. Five reference files carry the per-phase procedure and the ids. One offline script places work-plan dates; it is the only code and the only thing with unit tests. Live tool behavior is verified once per phase on a real ask and recorded in the reference files.

    Tech Stack: Markdown skill files; Python 3 stdlib script (csv, datetime, argparse, dataclasses); pytest; Drive, Docs, Sheets, Asana, Tableau, Cube, GitHub and BigQuery MCP tools at run time.

    Spec: docs/superpowers/specs/2026-10-27-project-charter-skill-design.md

    Global Constraints

    • Always uv run pytest and uv run python. Offline suite: uv run pytest tests/skills/test_project_charter_schedule.py.

    • No bare token env in any MCP tool string, commit message or issue text.
    • Nothing from a transcript, thread or ticket is quoted into a file in the repo, a GitHub issue, or a PR. Reference files use invented examples.
    • The charter lives in Drive only. No task writes a charter into the repo.
    • Date rules, verbatim from the spec: due dates are Fridays; a week is blocked when any in-scope region has a closure of 3 or more consecutive weekdays in it; blocked weeks are skipped and do not count toward a duration; a single closed day does not block; Thanksgiving week is blocked whatever the tab says; a Friday closed for any in-scope region moves to Thursday; a date past the calendar's last row is marked unverified: calendar not published.

    Review Focus

    1. A closure that straddles a weekend, Thursday through Monday, has 2 weekdays in one week and 1 in the next; neither week blocks. Pinned by Task 2 test_straddling_closure_blocks_neither_week.
    2. A project start that falls mid-week counts that week as the first working week; a start on a Saturday or Sunday counts the following week. Pinned by Task 3 test_start_midweek_counts_that_week and test_start_on_weekend_counts_next_week.
    3. An after that names no row, or names itself, must fail with the row names in the message rather than placing a date at the project start. Pinned by Task 3 test_unknown_after_raises.
    4. A region column value other than exactly Yes (yes, Y, blank) must not count as a closure; the tab is hand-maintained. Pinned by Task 1 test_region_yes_is_case_sensitive.
    5. An override that lands a follower in a blocked week must still skip that week for the follower. Pinned by Task 3 test_override_shifts_follower_past_blocked_week.

    @dataclass(frozen=True)
class Closure:
    start: date
    end: date      # inclusive
    name: str

REGIONS = ("Newark", "Camden", "Miami", "Paterson")

def parse_breaks(
    rows: Iterable[Mapping[str, str]],
    school_year_start: int,
    regions: Sequence[str],
) -> list[Closure]: ...

    rows are csv.DictReader rows with the tab's headers: Month, Date, Day, Holiday/Event, and one column per region. A row is a closure when any column in regions is exactly Yes. Month is a month name or abbreviation; months July to December take school_year_start, January to June take school_year_start + 1. Date is 11 or a range 21 - 1; a range whose end is a smaller day than its start crosses into the next month. A Date like Dec 21 - Jan 1 (month names inside the cell) is parsed the same way, the cell's months winning over the Month column. Rows with an empty Date or an unparseable one raise ValueError naming the row.

    Task 3: Place rows and the CLI

    Files:

    • Modify: .claude/skills/project-charter/scripts/schedule_dates.py

    Interfaces:

    • Consumes: parse_breaks, closed_days, blocked_weeks from Tasks 1-2.

    @dataclass(frozen=True)
class PlanRow:
    workstream: str
    name: str
    kind: str                 # "milestone" or "task"
    duration_weeks: int       # >= 1
    after: str | None = None  # another row's name
    override: date | None = None

@dataclass(frozen=True)
class Placed:
    row: PlanRow
    due: date
    rule: str                 # which rule placed the date
    note: str                 # "", "override", or "unverified: calendar not published"

def place(
    rows: Sequence[PlanRow],
    start: date,
    closures: Iterable[Closure],
    calendar_end: date,
) -> list[Placed]: ...

def read_plan(path: Path) -> list[PlanRow]: ...
# CSV headers: workstream,name,kind,duration_weeks,after,override

def main(argv: list[str] | None = None) -> int: ...

    Placement: a row's first working week is the week of its start, where its start is the project start (no after) or the Monday after its predecessor's due date. A start on a Saturday or Sunday begins the next week. Count duration_weeks working weeks forward, skipping blocked weeks; due is that week's Friday, rule = "friday". If that Friday is a closed day, due is the Thursday, rule = "closed friday -> thursday". An override replaces the due date, rule = "override", note = "override"; followers start from it. A due date after calendar_end gets note = "unverified: calendar not published". Rows are placed in dependency order; an after naming no row or its own row raises ValueError listing the row names.

    CLI:

    uv run python .claude/skills/project-charter/scripts/schedule_dates.py \
  --breaks breaks.csv --school-year 2026 --regions Newark,Camden \
  --start 2027-01-11 --plan plan.csv [--end 2027-06-18]

    Prints a markdown table: workstream, name, kind, due, rule, note. With --end, a final line lists rows due after it (the spec's close-before-end check). Exit 2 on a ValueError, message on stderr.
