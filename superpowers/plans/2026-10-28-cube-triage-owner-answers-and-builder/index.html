    Cube triage, owner answers, and the builder Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Add context-checked triage, owner answers in chat, and the Cube builder's commands and runbooks to the validator in PR #6160.

    Architecture: New logic goes in new modules beside the validator (triage.py, answers.py, builder.py), because pipeline.py is already 1,895 lines; pipeline.py and cli.py only gain thin call sites. Every judgment step (reading docs against a result, choosing tiers, sorting fields) is a skill step; every deterministic step is a command with offline tests. The tool still posts nothing: Claude posts what the analyst or owner approved.

    Tech Stack: Python 3.12, PyYAML, google-cloud-bigquery through the validator's Warehouse, Cube REST through cube_client.Cube, pytest with the fakes in tests/scripts/cube_validation/.

    Spec: docs/superpowers/specs/2026-10-28-cube-triage-owner-answers-and-builder-design.md (builds on docs/superpowers/specs/2026-10-26-cube-validation-and-build-skill-design.md).

    Global Constraints

    • Worktree: /workspaces/teamster/.claude/worktrees/cristinabaldor/feat/claude-cube-validation-and-build-skill. Run every command from it; git -C <worktree> for git.
    • Tests: uv run pytest tests/scripts/cube_validation -q (never bare uv run pytest: the rest of tests/ is live integration tests).
    • Stage files by name; write each commit message to a file in the session scratchpad and git commit -F <file>. End every message with Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com> and Refs #6150 (builder tasks: Refs #6157).
    • The tool posts nothing and never calls GitHub or Asana. Claude posts only what the analyst or the owner approved.
    • Nothing about one student or one staff member reaches GitHub, git, or a decision. A value prints only for a column in report._SHOWN_COLUMNS, and only for a group of report.MASK_BELOW (10) or more students; counts under 10 print as <10 (report.mask). Every other column is an identifier and fails closed (report._is_identifier).
    • Every BigQuery query goes through bq.Warehouse (priced first, run cap, daily cap --max-usd-per-day, view cache). No new bigquery.Client use.
    • Cube is reached over https only, except http to localhost or 127.0.0.1 (Task 10).
    • Time travel reaches 7 days: a hand check pinned to a moment older than that cannot run.
    • Docstrings and comments follow .claude/rules/comments.md: the constraint and the why, no measurements or history.
    • count_students means the enrollment headcount only (#6176); the builder never proposes another meaning under that name.

    Review Focus

    1. A triage value check on an identifier column (a student number captioned "ID", a name, an email) must neither compare nor print values; Task 4 pins it with test_value_check_skips_identifier_and_high_cardinality_columns.
    2. An owner's answers comment edited by hand, malformed, or naming decision ids that changed since review must write nothing at all; Task 9 pins it with test_record_answers_refuses_whole_comment_on_any_mismatch.
    3. An owner note with an email address or a long number must be refused before anything is written; Task 9 pins it with test_record_answers_refuses_email_and_number_runs_in_notes.
    4. A run whose moment is more than 7 days old reaches review: the questions JSON must say the pinned checks have expired instead of offering SQL that fails; Task 7 pins it with test_hand_checks_expire_after_7_days.
    5. A local Cube URL that only looks local (http://localhost.evil.com, http://127.0.0.1@evil.com) must be refused; Task 10 pins it with test_http_allowed_only_for_loopback_hosts.

    File Structure

    • Create scripts/cube_validation/triage.py: evidence and suggested calls for open items (Part A).
    • Create scripts/cube_validation/answers.py: example cells, pinned hand-check SQL, the review questions JSON, and parsing the owner's answers (Part B).
    • Create scripts/cube_validation/builder.py: Cube member listing, duplicate check, workbook re-inventory, gap-catalog parsing and the 3-source inventory (Part C).
    • Modify cube_client.py (meta, loopback http), config.py (fix_source, tasks:, filter notes, decision writer), pipeline.py (prove records filter notes; run saves hand-check material; review adds JSON), report.py (footnote, JSON block), moment.py and cli.py (dev-build dataset, new commands).
    • Create .claude/skills/cube-validation-answers/SKILL.md (owner) and .claude/skills/cube-builder/SKILL.md; modify .claude/skills/cube-validation/SKILL.md.
    • Tests: one new file per new module (test_triage.py, test_answers.py, test_builder.py) plus additions to existing test files.

    Rulings made while planning

    • triage is its own command after run, not part of run, so a re-run does not pay for Cube meta calls and value checks every time.
    • A "reference column" for value checks is one that is not PII-tagged, not named like an identifier, and has at most 50 values on both sides; values print only for the review's shown columns.
    • record-answers refuses emails and digit runs in notes. A name cannot be detected reliably by code, so both skills check for names before anything is posted or written.
    • fix_source stays quiet like every other call; the tool does not read GitHub, so "while its issue is open" is the analyst's re-run after it closes, not a check the tool makes.
    • Hand checks are built from SQL the run already executed, so review stays offline and free; only the per-cell student count is a new query.
