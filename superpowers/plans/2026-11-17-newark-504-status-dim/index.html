    Newark 504 Status Dimension Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Newark's AutoComm 504 column reads EdPlan plans from a new enrollment-bound mart, dim_student_504_status, instead of two intermediates.

    Architecture: A students-folder intermediate turns EdPlan 504 events into plan windows. The dim matches those windows to enrollment stints, as dim_student_iep_status does. The kipptaf AutoComm view joins the dim on student_enrollment_key and compares the window to today. Withdrawn students write back the roster's existing is_504.

    Tech Stack: dbt (BigQuery), kipptaf project. No Dagster or Newark wrapper change.

    Spec: docs/superpowers/specs/2026-11-16-newark-autocomm-504-design.md, section Revision 2026-11-17: 504 status dimension. Read it first; it overrides the original plan docs/superpowers/plans/2026-11-16-newark-autocomm-504.md wherever they differ.

    Global Constraints

    • Worktree: /workspaces/teamster/.claude/worktrees/anthonygwalters/feat/claude-newark-autocomm-504 (<wt>). git -C <wt>, absolute paths, uv run always. Branch anthonygwalters/feat/claude-newark-autocomm-504 (PR #6424).
    • kipptaf paths below are relative to <wt>/src/dbt/kipptaf/.
    • Dev build command (call it BUILD <selector>), run from <wt>: uv run dbt build --select <selector> --project-dir src/dbt/kipptaf --target dev --defer --favor-state --state /workspaces/teamster/src/dbt/kipptaf/target/prod 2>&1 | tail -n 30
    • Plans only: event_selector in 'Currently Valid: Section 504 Plan', 'Previous: Section 504 Plan'. Eligibility rows never enter.
    • No current_date in the intermediate or the dim. Only the rpt_ compares to current_date('{{ var("local_timezone") }}').
    • Active in the extract: is_current_plan, and effective_date_start_key <= today <= effective_date_end_key, on the roster row's own stint (student_enrollment_key).
    • Keys through macros (A7): {{ student_key(...) }}, {{ student_enrollment_key(student_number, _dbt_source_project, academic_year, entrydate) }}.
    • PII: tag student-level columns contains_pii: true; fixtures use made-up student numbers (1001-style). No real values in commits or GitHub.
    • No dedup (distinct, qualify, dbt_utils.deduplicate) anywhere. A grain failure means stop and report.
    • SQL rules S1-S20 (.claude/rules/dbt-sql.md), notably S8 (one level of nesting) and S10 (derived conditions become named columns upstream).

    Review Focus

    • A previous and a current plan on the same begin_date: the previous one must drop, or the intermediate's grain test fails. Pinned in Task 1.
    • A current plan followed by a later previous plan (one real student): the current plan keeps its own end date. Pinned in Task 1.
    • A plan spanning the summer: 2 dim rows, one per stint, each cut to its stint. Pinned in Task 2.
    • A previous plan whose end date has not passed, with no later plan: must yield 0 in the extract, because only current plans count. Pinned in Task 3.
    • A current plan that starts after today, inside the current stint: 0 until it starts. Pinned in Task 3.
