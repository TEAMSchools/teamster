    ADP Staging Failed-Deps Guard Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: stg_adp_workforce_now__workers does not build while any ADP workers partition's latest attempt is failed, and builds once that partition is rerun.

    Architecture: A new builder in core/automation_conditions.py ANDs a negated any_deps_match(execution_failed()) onto any condition. The dbt translator applies it to table models whose meta sets dagster.automation_condition.block_on_failed_deps: true, after it picks the cron or table condition. The staging model opts in through its properties YAML. The two roster tables drop the ADP freshness policy.

    Tech Stack: Dagster 1.13 AutomationCondition, dagster-dbt translator, dbt YAML, pytest with ephemeral instances.

    Spec: docs/superpowers/specs/2026-11-02-midnight-preemption-design.md, section "Phase 3" and its "Revision 2026-11-03" subsection. The revision overrides the Phase 3 mechanisms and decision test; the Phase 3 freshness bullets stand.

    Global Constraints

    • Meta key, verbatim: config.meta.dagster.automation_condition.block_on_failed_deps: true.
    • Tables only, like the cron override: a view or ephemeral model carrying the key keeps its view or union_relations condition.
    • The guard composes with whichever table condition the model gets (plain table or cron).
    • Guard expression: ~AutomationCondition.any_deps_match(AutomationCondition.execution_failed()).
    • No new Dagster+ alert policy. Freshness failures reach #dagster-alerts through the existing asset_alert__degraded policy.
    • Freshness: keep adp_wfn_policy on stg_adp_workforce_now__workers, remove it from int_people__staff_roster and int_people__staff_roster_history, leave stg_people__employee_numbers as is.
    • Always uv run. Tests run from the worktree root: /workspaces/teamster/.claude/worktrees/cbini/fix/claude-adp-staging-complete-pull.
    • Stage with git add -u (plus git add <new file> for a new file). Commit messages end with Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com> and carry Refs #6228.

    Review Focus

    1. A failed ADP partition from any date, not just tonight's 45, freezes staging until someone reruns it. This is intended ("stay frozen"). Today no partition is failed (2,146 of 2,146 materialized as of 2026-11-03), so the deploy does not freeze staging on arrival. The reviewer confirms nothing in the guard narrows it to a window.
    2. The trigger stays armed across held ticks. ADP updates that land while the guard holds must still request staging once the guard clears. Task 1's evaluation test pins this with two held ticks before the rerun.
    3. dbt merges model-level config.meta with the folder's +meta: {dagster: {group: adp_workforce_now}}. If it replaced it instead, the asset would change group. Task 2's manifest test asserts both keys.
    4. _get_dbt_meta or-shorts the whole top-level meta dict. The flag goes under config.meta, the same side as the folder meta. Task 2 asserts the asset key is unchanged.
    5. The flag on a view is ignored, and the flag composes with a cron override. Task 1's translator test pins both.
