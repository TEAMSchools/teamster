    KIPP Forward Early Apps Tracker Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Four rpt_gsheets__kfwd_early_apps_* models that feed a daily-refreshing Google Sheet tracking current seniors' early-application goals from Overgrad data.

    Architecture: Three domain intermediates in models/students/ hold every rule: an application-grain model, a senior-grain rollup, and a senior × criterion scaffold. Four thin rpt_ models shape them for the sheet's 4 tabs. An exposure in google-sheets.yml names the source sheet.

    Tech Stack: dbt (BigQuery), dbt unit tests, Connected Sheets.

    Spec: docs/superpowers/specs/2026-10-29-kfwd-early-apps-tracker-design.md

    Global Constraints

    • Worktree: /workspaces/teamster/.claude/worktrees/CGibson17/feat/claude-kfwd-early-apps-tracker (WT below). Every git call is git -C <WT>; every dbt call passes --project-dir <WT>/src/dbt/kipptaf. Always uv run.
    • Invoke the dbt-local-dev skill before the first dbt command (dev schema, --defer --state, and the prod manifest path). Run uv run dbt deps --project-dir <WT>/src/dbt/kipptaf in its own Bash call first.
    • Never write a --target staging or --target prod object. Dev builds only.
    • No student values in git, the PR, or the issue. Unit-test fixtures use Student A-style names and Example College-style colleges.
    • Current seniors: graduation_year = {{ var("current_academic_year") + 1 }}.
    • The 3 high schools, by Overgrad school__name: KIPP Cooper Norcross High School, KIPP Newark Collegiate Academy, KIPP Newark Lab High School.
    • Early due_date__type: early_action, early_action_2, early_decision, early_decision_2, single_choice_early_action. ED = early_decision*; EA = the other 3.
    • Submitted status: Applied, Accepted, Denied, Deferred, Waitlisted, Enrolled.
    • URM rate: stg_kippadb__account.adjusted_6_year_minority_graduation_rate, on nces_id = cast(university__ipeds_id as string). Null rate never qualifies and is never near the bar.
    • Full need: column is_full_need, always true.
    • Every join between int_overgrad__students and int_overgrad__admissions includes _dbt_source_project (rule A10).
    • Counts are distinct university__id.
    • SQL follows .claude/rules/dbt-sql.md; YAML follows .claude/rules/dbt-yaml.md. Every model and column has a description:. rpt_ tests set config: severity: error.
    • PII tags (tiers 1 to 3 from .claude/rules/ferpa-pii.md, column level): student name, GPA, GPA band, criterion statuses, and every application list. The Summary model is untagged (aggregate).
    • overgrad_student_id is the grain key in every student-level model. It stays in the model for tests and is left out of the Connected Sheets column picks.
    • Lint every changed SQL, YAML, and markdown file before pushing: cd <WT> && /workspaces/teamster/.trunk/tools/trunk check --force --no-fix <files> </dev/null.

    Review Focus

    1. A flagged senior with no GPA: band No GPA, every criterion N/A, still in N. Test in Task 2.
    2. An early application whose college has no URM rate: never qualifying, never near the bar. Test in Task 3.
    3. A flagged senior whose only early application is Withdrew: counted as not submitted, so Section A. Test in Task 2.
    4. URM exactly on a bar (80.0 qualifies; 75.0 is near the bar; 74.9 is neither). Test in Task 3.
    5. A GPA band with 0 seniors at 1 school: Summary shows -, not a divide error. Test in Task 5.

    Files:

    • Create: src/dbt/kipptaf/models/students/intermediate/int_students__early_applications.sql

    • Step 1: Write the unit test test_int_students__early_applications_classification in the properties YAML. Given 6 admissions: early_decision/Applied, early_decision_2/Will Apply, single_choice_early_action/Accepted, early_action/Withdrew, regular/Applied, priority/Applied, and 2 accounts (one with rate 80.0, one with null rate). Expect 4 rows, with application_type ED, ED, EA, EA; is_submitted true, false, true, false; the rate joined for the matching IPEDS id and null otherwise; is_full_need true on every row.

    • Step 2: Run it and see it fail uv run dbt test --select "int_students__early_applications,test_type:unit" --project-dir <WT>/src/dbt/kipptaf Expected: FAIL (model does not exist).
    • Step 3: Write the model. Filter to the early types in Global Constraints. Left join the account on IPEDS id.
    • Step 4: Add the grain test dbt_utils.unique_combination_of_columns on _dbt_source_project, admission_id. It also catches an IPEDS id on 2 Salesforce accounts, which would fan out rows.
    • Step 5: Run the unit test. Expected: PASS.
    • Step 6: Commit feat(dbt): add int_students__early_applications.

    • List formats, alphabetical by college, joined with ,: submitted Example College (ED) 77% (rate rounded to whole number; no rate when null); will-apply Example College (EA).

    • Step 1: Write unit test test_int_students__early_applications_rollup. Given 5 current seniors at the 3 schools plus 1 at KIPP MS Completers (Newark) and 1 with graduation_year of next year. Cases: Student A flagged, GPA 3.96, 2 submitted applications to 2 colleges; Student B flagged, null GPA, 0 applications; Student C flagged, GPA 3.10, 1 Withdrew application and 1 Will Apply due 2026-11-01; Student D unflagged, GPA 3.50, 1 submitted application; Student E GPA 3.745. Override vars: {current_academic_year: 2026}. Expect 5 rows (the MS Completers and next-year seniors excluded). Student B band No GPA, count 0. Student C count 0, will-apply list populated, earliest date 2026-11-01. Student E unweighted_gpa 3.75, band 3.75+.

    • Step 2: Add a second unit test test_int_students__early_applications_rollup_distinct_colleges: 1 senior with 2 submitted rows for the same university_id. Expect submitted_early_count = 1.
    • Step 3: Run both and see them fail.
    • Step 4: Write the model. Spine from int_overgrad__students; left join Task 1 on overgrad_student_id and _dbt_source_project.
    • Step 5: Grain test on _dbt_source_project, overgrad_student_id.
    • Step 6: Run the unit tests. Expected: PASS.

    Task 3: Senior × criterion scaffold

    Files:

    • Create: src/dbt/kipptaf/models/students/intermediate/int_students__early_application_criteria_scaffold.sql
    • Create: .../properties/int_students__early_application_criteria_scaffold.yml

    Interfaces:

    • Consumes: Tasks 1 and 2.
    • Produces: 1 row per senior (any flag) × each criterion of their band. Seniors in Below 3.00 or No GPA get no rows. Columns: _dbt_source_project, overgrad_student_id, gpa_band, criterion_code, criterion_sort, criterion_label, required_count, urm_bar, qualifying_count, near_bar_count, is_met (bool), is_near_miss (bool), qualifying_colleges, near_bar_colleges, what_they_have, what_would_close_it.
    criterion_code sort band label type bar required
    ed_80_full_need 1 3.75+ 1 ED, full need, 80%+ URM ED 80 1
    ea_78 2 3.75+ 2 EA, 78%+ URM EA 78 2
    early_80_full_need 3 3.50-3.74 1 ED/EA, full need, 80%+ URM early 80 1
    additional_68 4 3.50-3.74 2 additional early, 68%+ URM early 68 2
    early_68 5 3.00-3.49 3 early, 68%+ URM early 68 3
    • Qualifying: submitted, right type, urm_graduation_rate >= bar, and is_full_need for the 2 full-need rules. For additional_68, set aside the alphabetically first qualifying early_80_full_need college, then count the rest.
    • Near bar: submitted, right type, bar - 5 <= rate < bar.
    • is_near_miss: not is_met and either required_count = 1 and near_bar_count >= 1, or required_count > 1 and (qualifying_count = required_count - 1 or qualifying_count + near_bar_count >= required_count).
    • what_they_have: Qualifying: <list>; Near the bar: <list>, omitting an empty part; each item uses the Task 2 submitted format.

    • what_would_close_it, only when is_near_miss: for a 1-school rule, An <ED|ED or EA> college at <bar>%+ (closest: <college> at <rate>%, <gap> points short) with the gap to 1 decimal; otherwise <n> more <ED|EA|early> college(s) at <bar>%+ where n = required_count - qualifying_count.

    • Step 1: Unit test test_..._criteria_scaffold_3_75_band. 2 seniors in 3.75+. Senior A: ED at 95.8, EA at 79.1 and 88.8. Senior B: ED at 78.2, EA at 79.1 and 73.6. Expect Senior A ed_80_full_need and ea_78 met, not near misses. Senior B both not met and both near misses; ed_80_full_need close text An ED college at 80%+ (closest: <college> at 78.2%, 1.8 points short); ea_78 close text 1 more EA college at 78%+.

    • Step 2: Unit test test_..._criteria_scaffold_narrow_near_miss. 2 seniors in 3.00-3.49. Senior C: 0 qualifying, 1 application at 65.0: not a near miss. Senior D: 2 qualifying and 1 at 63.0: near miss.
    • Step 3: Unit test test_..._criteria_scaffold_additional. 1 senior in 3.50-3.74 with early applications at 92, 88, and 70. Expect early_80_full_need met; additional_68 met with qualifying_count 2 (88 and 70 count; the alphabetically first of 92 and 88 is set aside).
    • Step 4: Unit test test_..._criteria_scaffold_edges (Review Focus 2 and 4). 3.75+ senior with ED at 80.0 (met), a second 3.75+ senior with ED at 75.0 (near miss) and EA at null rate (not counted), a third with ED at 74.9 (not met, not a near miss).
    • Step 5: Run all 4 and see them fail.
    • Step 6: Write the model. Criteria come from a literal unnest of structs matching the table above, joined to the rollup on gpa_band.
    • Step 7: Grain test on _dbt_source_project, overgrad_student_id, criterion_code.
    • Step 8: Run the unit tests. Expected: PASS.
    • Step 9: Commit feat(dbt): add early application criteria scaffold.
