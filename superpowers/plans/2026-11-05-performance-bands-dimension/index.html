    Performance Bands Dimension Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Give every Illuminate and Focus Assessments score in Cube its band set, cut points and a mastery-relative level (At/Above, Approaching, Below, Far Below), and prove the level against the DDI Suite DKI View.

    Architecture: The Focus package's band numbering moves into its own model. A kipptaf domain intermediate unions Illuminate and Focus bands at band grain and derives the level; dim_performance_bands reads it, the scores fact gains performance_band_key, and a new Cube cube joins in. The validator compares the level against 2 DKI sheets.

    Tech Stack: dbt (BigQuery) in src/dbt/focus and src/dbt/kipptaf; Cube YAML in src/cube/model; scripts/cube_validation.

    Spec: docs/superpowers/specs/2026-11-05-performance-bands-dimension-design.md

    Worktree: /workspaces/teamster/.claude/worktrees/cristinabaldor/feat/claude-band-set-dimension (branch cristinabaldor/feat/claude-band-set-dimension). Every git call uses git -C <worktree>; every dbt, Python and pytest call uses uv run from the worktree, except the validator runner (Task 7).

    Global Constraints

    • Source literals: illuminate and apex, exactly as int_assessments__response_rollup.source spells them.
    • performance_band_key = generate_surrogate_key([source, performance_band_set_id, band_number]) on both the dim and the fact. The fact wraps it in if(<band number> is not null, ..., cast(null as string)).
    • mastery_level values, exactly: At/Above, Approaching, Below.
    • Level rule: At/Above = band_number >= mastery_band_number; Approaching = band_number = mastery_band_number - 1; Below = lower. is_far_below = band_number = 1 and not is_mastery.
    • A set that breaks a level assumption (mastery not contiguous to the top band, band_number out of minimum_score order, or mastery starting below band 3) gets null mastery_level and null is_far_below on every band. Its guard test runs at warn (spec revision 2026-11-05).
    • Focus mastery: Level 3 and above on every Focus set.
    • Only band sets used by internal scores (int_assessments__response_rollup, is_internal_assessment) are in the union and the dim.
    • Below and Far Below shares are percents of distinct students (student_enrollment_key), over students with a banded score.
    • Cut values are percent correct, 0 to 100.
    • Every new or changed dbt column and Cube member has a description:; a one-column Cube member's description equals its dbt column's, registered in TWINS.
    • No movement column and no Cube text about movement beyond mastery_level's ai_context (spec, Cube section).

    Review Focus

    1. A score with a band number but no band set (merged split standards) gets a null key, never a placeholder hash. Test: Task 4 FK-population query.
    2. A standard on a different band set from its assessment keys to its own set. Test: Task 4 query comparing the fact key's set to the rollup row's set.
    3. Focus set 4 spells 2 bands "Low Level 1". Band identity is the band number, never the label. Test: Task 3 unit test row with a duplicate label.
    4. The fact's band number is numeric and the Focus band number is int64; both must hash to the same string. Test: Task 4 FK-population query returns 0 orphans.
    5. A new Illuminate set breaks a level assumption (mastery at band 2, a gap). Its bands get a null level instead of a wrong one, and nothing stops refreshing. Test: Task 3 unit-test set E.
