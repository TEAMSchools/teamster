    Google Forms Latest Submission Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Every survey report keeps one latest Google Forms submission per respondent, per subject, per administration, and Miami Re-Commitment families resolve to students.

    Architecture: A new domain model, int_surveys__submission_subjects, holds every subject rule. int_surveys__survey_submissions joins it and re-ranks round_rn. The facts filter round_rn = 1. The renewal feed, the Manager Survey details and the SCD report read the shared subject instead of their own copies.

    Tech Stack: dbt (kipptaf project) on BigQuery; dbt unit tests; BigQuery MCP for prod checks.

    Spec: docs/superpowers/specs/2026-10-26-google-forms-latest-submission-design.md

    Global Constraints

    • Worktree: /workspaces/teamster/.claude/worktrees/cbini/feat/claude-google-forms-latest-submission. Run every command from <worktree>/src/dbt/kipptaf, and use git -C <worktree> for git.
    • Always uv run dbt. Dev builds use --target dev --defer --favor-state --state /workspaces/teamster/src/dbt/kipptaf/target/prod (the main checkout's prod manifest, absolute path). Never --target staging or --target prod.
    • Every new or modified column gets a description:. Student numbers, employee numbers, rank_respondent and rank_subject get config.meta.contains_pii: true.
    • Commits end with Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com> and carry Refs #5978. No PII values in commits, PR text or comments: counts only.
    • SQL rules that bite here:
    • S1: no qualify.
    • S9: cast once, in a CTE.
    • S10: where/on plain comparisons only.
    • S17: union branches list the same columns in the same order.
    • S20: comment every business-rule literal.
    • Before each commit: /workspaces/teamster/.trunk/tools/trunk check --force --no-fix <files> </dev/null. Fix lint findings; formatting is the commit hook's.
    • The Alchemer archive (source("surveys", "int_surveys__alchemer_submissions")) is frozen. Do not edit it.

    Review Focus

    1. A Google Forms submission with a null term_code must get round_rn = 1, including several from one respondent. Pinned by the Task 2 unit test row no_term_a / no_term_b.
    2. One approver rating two staff in one term must keep two latest rows. Pinned by the Task 2 rows approver_subject_1 / approver_subject_2.
    3. A family submission with no email must rank by student, not alone. Pinned by the Task 2 rows family_old / family_new.
    4. A non-numeric or 4-digit family answer must give a null student, not 8400-prefixed junk. Pinned by Task 1 row family_bad.
    5. A Manager Survey or Renewal row whose subject answer has no bracketed number must give a null subject and still rank, on respondent alone. Pinned by Task 1 row no_bracket.

    Task 1: Shared subject model

    Files:

    • Create: models/surveys/intermediate/int_surveys__submission_subjects.sql
    • Create: models/surveys/intermediate/properties/int_surveys__submission_subjects.yml

    Interfaces:

    • Consumes: ref("int_google_forms__form_responses") (question grain; columns form_id, response_id, info_title, item_abbreviation, text_value).
    • Produces: int_surveys__submission_subjects, one row per survey_id, survey_response_id. Columns:
    • survey_id string
    • survey_response_id string
    • subject_employee_number int64
    • respondent_student_number int64

    Rows exist only for submissions with at least one subject question answered.

    • Step 1: Confirm the keys in prod. Query kipptaf_google_forms.int_google_forms__form_responses (BigQuery MCP). Count submissions per info_title where item_abbreviation is in ('subject_employee_number', 'employee_name', 'family_respondent_number'). Expected: Manager Survey 8,285; Renewal Approval Tool Processing 12,664; Performance Management Score Change Request Form 53; the Re-Commitment title 2,257, give or take new submissions. If an abbreviation is missing, stop and ledger it.

    • Step 2: Write the yml with the unit test first.

    • Model description, column descriptions and PII tags.
    • A model-level dbt_utils.unique_combination_of_columns on survey_id, survey_response_id at severity: error.
    • Unit test test_int_surveys__submission_subjects_rules. Mock int_google_forms__form_responses with format: sql (a select of literal rows), with these rows:

    • Step 3: Run it to watch it fail. uv run dbt test --select int_surveys__submission_subjects,test_type:unit --target dev Expected: FAIL. The model SQL does not exist, or the compile error names the missing model.

    • Step 4: Write the model.

    • Filter to the three abbreviations.
    • Group by form_id, response_id. Take max(if(...)) per rule:
      • Bracket rule: regexp_extract(text_value, r'\((\d{6})\)'), then safe_cast to int64 in a later CTE (S8/S9).
      • Family rule: only when info_title is the Re-Commitment title and regexp_contains(text_value, r'^\d{5,6}$').
