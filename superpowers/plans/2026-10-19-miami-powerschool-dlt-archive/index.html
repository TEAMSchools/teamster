    Miami PowerSchool dlt archive Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Give Miami off-by-default dlt PowerSchool assets, load the full archive table set from the still-running server, rebuild kippmiami_powerschool from dlt, and close #5409.

    Architecture: Miami reuses build_powerschool_dlt_assets with its own assets.yaml and no triggers. The PowerSchool dbt package gains 12 dlt staging models, off by default. A temporary powerschool: block in kippmiami builds the dlt variant into dev, a comparison against prod gates the user's prod build, and the block is removed before merge.

    Tech Stack: Dagster+ (GKE, k8s_job_executor), dlt over an SSH tunnel to Oracle, dbt-bigquery, 1Password operator.

    Spec: docs/superpowers/specs/2026-10-19-miami-powerschool-dlt-archive-design.md

    Global Constraints

    • One PR on cbini/feat/claude-miami-powerschool-dlt-archive, linked to #5409; it closes #5409 on merge.
    • Worktree: /workspaces/teamster/.claude/worktrees/cbini/feat/claude-miami-powerschool-dlt-archive. Use absolute paths and git -C <worktree> on every call; uv run for every python/dbt/dagster.
    • No sensor or schedule for Miami PowerSchool. Assets run only by hand.
    • The rebuilt archive table set equals today's, except the 2 retired package models below, which stay frozen.
    • Post-hooks, verbatim from commit 00bd5eaad7: stg_powerschool__students update {{ this }} set student_number = student_number + 8400000000 where true; delete from {{ this }} where yearid > 35 on assignmentcategoryassoc, assignmentsection, attendance, attendance_code, cc, fte, gen, gradecalculationtype, gradeformulaset, gradeschoolconfig, prefs, storedgrades, termbins, terms; stg_powerschool__calendar_day delete from {{ this }} where date_value >= '2026-07-01'.
    • No PII values in commits, PR body or comments: counts and column names only.
    • --target prod dbt runs, .k8s applies, Dagster+ pool settings, and all warehouse DDL are the user's steps. Hand them over; do not run them.
    • dagster_kippmiami_dlt_powerschool is not branch-isolated. A branch deployment run writes the prod dataset; that is intended here.
    • Never drop kippmiami_powerschool, dagster_kippmiami_dlt_powerschool, the src_powerschool__* externals or the GCS Avro files.

    Table set

    The archive has 58 stg_powerschool__* tables and 43 base_/int_ tables (kippmiami_powerschool, queried 2026-10-19). Load these 58 dlt tables:

    • 45 with an existing package dlt model: assignmentcategoryassoc assignmentscore assignmentsection attendance attendance_code attendance_conversion_items bell_schedule calendar_day cc courses cycle_day districtteachercategory fte gen gradecalcformulaweight gradecalcschoolassoc gradecalculationtype gradeformulaset gradescaleitem gradeschoolconfig gradeschoolformulaassoc gradesectionconfig log pgfinalgrades reenrollments roledef schools schoolstaff sections sectionteacher spenrollments storedgrades studentcorefields students studenttest studenttestscore teachercategory termbins terms test testscore u_clg_et_stu u_clg_et_stu_alt users userscorefields. Cursor columns: copy each from src/teamster/code_locations/kippnewark/powerschool/sis/dlt/config/assets.yaml.
    • 12 needing a new package dlt model: codeset emailaddress originalcontactmap person personaddress personaddressassoc personemailaddressassoc personphonenumberassoc phonenumber prefs studentcontactassoc studentcontactdetail.
    • 1 district-level: u_studentsuserfields. Its archive table came from a kippmiami model deleted in 223c10eb60; cursor whenmodified (Newark).

    45 + 12 + 1 = 58, one dlt table per archive staging table. The spec's "46 have a dlt model" counted u_studentsuserfields, which is a district model, not a package one.

    Frozen, not rebuilt: int_powerschool__student_contacts and int_powerschool__student_contacts_pivot. The package disables both in their properties YAML (retired in 06f780155b), and a model-level enabled: false beats a root-project config, so kippmiami cannot turn them on. Nothing reads them.

    Review Focus

    1. A new package model enabled in an NJ region breaks its build. Expected: none of the 12 resolve in kippnewark, kippcamden or kipppaterson. Test in Task 4.
    2. A table that is empty on the Miami server lands no BigQuery table, so its staging model fails at build. Expected: every one of the 58 tables exists in dagster_kippmiami_dlt_powerschool after the load. Check in Task 3.
    3. Oracle DATE columns land TIMESTAMP and break a staging contract. Expected: every staging model builds with its contract enforced. Covered by Task 5's dev build.
    4. A post-hook silently misses its target under the dlt variant. Expected: 0 rows with yearid > 35 in the 14 tables, 0 calendar_day rows on or after 2026-07-01, and every student_number >= 8400000000. Check in Task 5.
    5. "Off" leaves the code location unloadable. Expected: the branch deployment loads kippmiami cleanly after the final off commit. Check in Task 8.
