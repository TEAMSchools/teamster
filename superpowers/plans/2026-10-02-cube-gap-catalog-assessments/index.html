    Notes

    • Headline finding: none of this dashboard's measures are cube-covered. The student_assessment_scores Cube cube reads kipptaf_marts.fct_assessment_scores_enrollment_scoped only — its own view description explicitly scopes to "Illuminate interims, NJ/FL state assessments, and vendor benchmarks (i-Ready, DIBELS, STAR)" and omits SAT/ACT/PSAT/AP entirely. Those live in a sibling mart, kipptaf_marts.fct_assessment_scores_student_scoped (src/dbt/kipptaf/models/marts/facts/fct_assessment_scores_student_scoped.sql), which no Cube cube reads at all (grep -rl "student_scoped" src/cube/model returns nothing). This is NOT the "neither fct exists" situation the task prompt hinted at — the fact table exists, at essentially the right grain (one row per student × assessment × test date for college-entrance; per student × AP course × year for AP), and already computes scale_score, max_scale_score, superscore, running_max_scale_score, rank, and is_mastery (using the exact College Board/AP benchmark cutoffs this dashboard hand-rolls in Tableau calcs). The gap is purely a missing Cube cube/view wiring it up, not missing dbt modeling, for the score-only measures.
    • fct_assessment_scores_student_scoped's own SELECT does not project scope/subject_area/academic_year/test_type as columns — they're hash inputs only. They resurface via a join through dim_assessment_administrations.assessment_key → dim_assessments (category=scope, academic_subject=subject_area, title=AP course name / SAT-ACT-PSAT label). A new Cube cube over the student-scoped fact needs that 2-hop join path to expose the dimensions this dashboard actually uses.
    • A meaningful share of measures are genuinely mart-missing, not just Cube-missing: AP course-enrollment participation (denominator for every "% enrolled in AP" / "% tests attempted" measure), Dual Enrollment grades, CCR course/section/teacher, and every benchmark-goal threshold (they live in two KIPP Forward Google Sheets — stg_google_sheets__kippfwd__scaffold and stg_google_sheets__kippfwd__expected_assessments — not in any dimensional mart). Wiring Cube to the existing fact table would light up the raw-score measures but leave every goal-comparison and participation-rate measure dark.
    • GPA fields on the Roster (cumulative_y1_gpa, cumulative_y1_gpa_projected, college_match_gpa/bands) and KTC Cohort were left unknown — out of this pass's assessment-domain scope; a GPA-mart/Cube check would resolve them quickly (dim_students or a GPA fact likely already covers them elsewhere in Cube).
    • Two worksheet names carry a [Test] prefix ("[Test] Over Time - Met HS/CR Benchmark (Cohort)" / "(Tested)") and sit directly on the published "Over Time" dashboard — not hidden, not scratch. Treated as in-scope per the "include and flag" rule; the naming suggests these may be WIP despite being live.
    • Near-identical sheet variants were collapsed into one row each: the 3 "Key Metrics % Goals by NJ/Region/School" sheets (same calc, different grouping dimension), the 3 "Benchmarks - Combined/EBRW/Math" sheets (same calc, subject_area filter differs), and the AP "% ... by Tests Taken - All Taken / Expected" pair.
    • Excluded as pure formatting/layout, not listed as rows: 4 title-only worksheets (AP Overview - Title, DE Overview - Title, Over Time - Title, Roster Table - Title, all a literal "Title" string calc) and 2 Google-Sheet-link placeholder worksheets (Roster - Camden GSheet, Roster - Newark GSheet, both a literal 'text' calc — link-out buttons, no data).
    • Region classification for AP Overview / DE Overview rests on the workbook's own "NJ Only" image banner plus the PowerSchool-only lineage of their source rpt_ models (Miami runs Focus, not PowerSchool) — genuinely a data-presence argument, not a SQL WHERE region = ... filter, since neither rpt_ model filters on region explicitly. Whether Paterson (also PowerSchool) actually carries AP/DE data today was not verified against warehouse rows (no-PII instruction; would need a row-count-only check against prod).
