### Notes

- **Workbook-download race condition**: the first `download-workbook` call
  returned content for a _different_ workbook (HS Early Warning Dashboard) —
  almost certainly a shared-tmp-path collision with a concurrent sibling session
  also inventorying a dashboard. Caught via hash-verification before parsing;
  re-downloaded and re-verified (dashboard names matched the `get-workbook`
  views list) before any analysis below was built. All scratch-directory
  intermediates used a uniquely-prefixed path
  (`ops_dashboard_extract2/opsdash_awalters_*`) after discovering the shared
  scratchpad also held generically-named files from other concurrent sessions.
- **Region default is NOT "all regions" on most sheets** — every
  Attrition/Demographics/SPED/Lunch/LEP worksheet's region quick-filter was last
  saved with only `Paterson` (+ null) selected; a viewer who opens the workbook
  without touching the filter sees Paterson-only numbers on those pages. The
  filter control IS visible and user-changeable on every dashboard (confirmed
  via `<zone type-v2="filter" param="...region...">` presence), so this is a
  saved-default artifact, not a hard lock — but it's the same shape of issue the
  Attendance pilot flagged, just one notch softer (changeable vs. hard-coded).
  The Enrollment Dashboard, Enrollment (Sch/Gr), and Recent Enrollment Changes
  sheets save with the filter cleared (all regions).
- **Internal field names routinely mismatch their displayed captions** on this
  datasource (e.g. a field literally named `# Enrolled - Am Indian (copy)`
  captions as "# Enrolled - Asian", and its formula does compute the Asian
  count) — this is copy-paste residue in the workbook's calculated-field
  history, not a logic bug. Captions (what end users see) were used as the
  metric name throughout; verify against the underlying formula before trusting
  a field's bare internal name. "# Enrolled - Transgender" is the one exception
  that's a real stub (`CALC[0]`, always zero) — flagged separately above. `
- **`Attrition Analysis - Demographics` dashboard is not in the server's
  published-views list** returned by `get-workbook` (only 7 views listed; this
  workbook has 9 sheet-tabs marked as dashboards in the `.twb`, of which one is
  an explicit `[Archive]` and this one is unexplained). Included above per
  instructions ("hidden" dashboards stay in scope when in doubt), but its
  hidden/unpublished-on-server status should be confirmed with the dashboard
  owner before relying on it for migration scope.
- A large share of this dashboard's _unique_ logic (ADE, Target Enrollment,
  Enrollment Need/Surplus, % Retention, all attrition/exit-code tracking) has
  **no mart or Cube equivalent at all** — it lives only inside
  `rpt_tableau__ops_dashboard`'s SQL or in Tableau calculated fields layered on
  top of it. This is a bigger mart-missing share than a typical KPI dashboard; a
  Cube migration of this workbook is mostly new modeling work (finance targets,
  attrition/exit-code events), not a re-pointing exercise.
- Demographic/status breakdowns (race, gender, ELL, IEP/SPED, meal eligibility,
  grade, school, region, retained-year, entry/exit date) are comparatively well
  covered by `student_attendance_enrollment_daily_view` via its
  `student_school_enrollments` / `student_enrollment_status` / `students` joins
  — these are "cube-covered" above, but note the task hint's claim that
  `student_school_enrollments`/`student_enrollment_status` have their own
  exposed views is **not accurate**: neither cube has a view of its own under
  `src/cube/model/views/students/` (only
  `student_attendance_enrollment_daily_view`,
  `student_attendance_enrollment_periods_view`, and
  `student_section_enrollments_view` exist). Their dimensions reach the surface
  only indirectly, through the daily-attendance view's join path.

### Notes

- **Grain mismatch is the main judgment call.** Both in-scope dashboards are
  row-level QA worklists (which specific student/teacher/module has a problem),
  not aggregate reporting. Cube is built for aggregate, access-controlled
  analytics — so even where the underlying raw column is cube-covered (student
  name, school, assessment title, percent_correct), the dashboard's actual job
  (drill to the offending row and fix it in the source system) isn't something a
  Cube view does today. Treat "cube-covered" here as "the attribute exists in
  Cube," not "Cube can replace this dashboard."
- **dim_students decodes mask nulls.** `race` always resolves to a label
  (`'Not Listed'` fallback) and can't reproduce the "Missing Ethnicity" /
  "Missing Race/Ethnicity" raw-null checks — this is the opposite of a
  pattern-match "name doesn't need to match" case; the VALUES actually diverge
  (decoded non-null vs raw null). Confirmed by reading `dim_students.sql`
  directly rather than assuming the Cube `race` dimension covers it.
  `gender_identity` and `birth_date` ARE raw passthroughs (no coalesce), so
  those two are legitimately mart-ready.
- **Three dashboards in the .twb are not live.** "RC Comment Audit" explicitly
  says it moved to `GradebookDashboard/Appendix-CommentAudit` (another workbook)
  — that functionality should not be scoped into this dashboard's replacement at
  all. "Assessment Audit - Zero-Answered" has no worksheet zone of its own (pure
  instructional text + a drill-through target), so it carries no metrics to
  inventory. "(Archived)" is a stale duplicate.
- **Asana blocker reconciliation**: `fct_internal_assessments` and
  `fct_enrollment` genuinely do not exist under those names — the closest
  equivalents are `fct_assessment_scores_enrollment_scoped` / `_student_scoped`
  and `dim_student_enrollments` (no "fct_enrollment"; it's dimensional, not a
  fact). `dim_students` and `dim_locations` DO exist today (contrary to how the
  blocker list reads) — they just don't carry the data-quality-check columns
  this dashboard needs.
- A shared scratchpad collision occurred mid-task: a sibling agent's parse
  script and `.twb` extraction overwrote files in the shared `twbx_extract/` and
  a same-named script in the scratchpad root (both belong to a different
  dashboard, "Promotional Status Dashboard" / "Literacy Dashboard"). Recovered
  by moving this dashboard's own copy of the `.twb` and a uniquely-named script
  into a dedicated `dqd_work/` subfolder; no data from this inventory was lost,
  but flagging in case other dashboards' output files show similar
  contamination.
