### Notes

- **Headline finding**: none of this dashboard's measures are `cube-covered`.
  The `student_assessment_scores` Cube cube reads
  `kipptaf_marts.fct_assessment_scores_enrollment_scoped` only — its own view
  description explicitly scopes to "Illuminate interims, NJ/FL state
  assessments, and vendor benchmarks (i-Ready, DIBELS, STAR)" and omits
  SAT/ACT/PSAT/AP entirely. Those live in a **sibling** mart,
  `kipptaf_marts.fct_assessment_scores_student_scoped`
  (`src/dbt/kipptaf/models/marts/facts/fct_assessment_scores_student_scoped.sql`),
  which no Cube cube reads at all (`grep -rl "student_scoped" src/cube/model`
  returns nothing). This is NOT the "neither fct exists" situation the task
  prompt hinted at — the fact table exists, at essentially the right grain (one
  row per student × assessment × test date for college-entrance; per student ×
  AP course × year for AP), and already computes `scale_score`,
  `max_scale_score`, `superscore`, `running_max_scale_score`, `rank`, and
  `is_mastery` (using the exact College Board/AP benchmark cutoffs this
  dashboard hand-rolls in Tableau calcs). The gap is purely a missing Cube
  cube/view wiring it up, not missing dbt modeling, for the score-only measures.
- `fct_assessment_scores_student_scoped`'s own SELECT does **not** project
  `scope`/`subject_area`/`academic_year`/`test_type` as columns — they're hash
  inputs only. They resurface via a join through
  `dim_assessment_administrations.assessment_key` → `dim_assessments`
  (`category`=scope, `academic_subject`=subject_area, `title`=AP course name /
  SAT-ACT-PSAT label). A new Cube cube over the student-scoped fact needs that
  2-hop join path to expose the dimensions this dashboard actually uses.
- A meaningful share of measures are genuinely **mart-missing**, not just
  Cube-missing: AP course-**enrollment** participation (denominator for every "%
  enrolled in AP" / "% tests attempted" measure), Dual Enrollment grades, CCR
  course/section/teacher, and every benchmark-**goal threshold** (they live in
  two KIPP Forward Google Sheets — `stg_google_sheets__kippfwd__scaffold` and
  `stg_google_sheets__kippfwd__expected_assessments` — not in any dimensional
  mart). Wiring Cube to the existing fact table would light up the raw-score
  measures but leave every goal-comparison and participation-rate measure dark.
- GPA fields on the Roster (`cumulative_y1_gpa`, `cumulative_y1_gpa_projected`,
  `college_match_gpa`/bands) and `KTC Cohort` were left `unknown` — out of this
  pass's assessment-domain scope; a GPA-mart/Cube check would resolve them
  quickly (dim_students or a GPA fact likely already covers them elsewhere in
  Cube).
- Two worksheet names carry a `[Test]` prefix ("[Test] Over Time - Met HS/CR
  Benchmark (Cohort)" / "(Tested)") and sit directly on the published "Over
  Time" dashboard — not hidden, not scratch. Treated as in-scope per the
  "include and flag" rule; the naming suggests these may be WIP despite being
  live.
- Near-identical sheet variants were collapsed into one row each: the 3 "Key
  Metrics % Goals by NJ/Region/School" sheets (same calc, different grouping
  dimension), the 3 "Benchmarks - Combined/EBRW/Math" sheets (same calc,
  `subject_area` filter differs), and the AP "% ... by Tests Taken - All Taken /
  Expected" pair.
- Excluded as pure formatting/layout, not listed as rows: 4 title-only
  worksheets (`AP Overview - Title`, `DE Overview - Title`, `Over Time - Title`,
  `Roster Table - Title`, all a literal `"Title"` string calc) and 2
  Google-Sheet-link placeholder worksheets (`Roster - Camden GSheet`,
  `Roster - Newark GSheet`, both a literal `'text'` calc — link-out buttons, no
  data).
- Region classification for AP Overview / DE Overview rests on the workbook's
  own "NJ Only" image banner plus the PowerSchool-only lineage of their source
  rpt_ models (Miami runs Focus, not PowerSchool) — genuinely a data-presence
  argument, not a SQL `WHERE region = ...` filter, since neither rpt_ model
  filters on region explicitly. Whether Paterson (also PowerSchool) actually
  carries AP/DE data today was not verified against warehouse rows (no-PII
  instruction; would need a row-count-only check against prod).

### Notes

- **Two whole dashboards in the .twb are not live.** "Standards Over Time" and
  "Module Score Distribution" carry
  `repository-location path=".../workbooks/AssessmentDashboard"` — a different,
  legacy Tableau workbook — rather than `.../workbooks/DDISuite`. They are
  absent from `get-workbook`'s published `views` list, so they were treated as
  out of scope rather than "hidden-but-live." Both are themed around standards
  mastery, which is suggestive given the open DDI gaps below, but nothing
  confirms they're the same logic as #4167/#4168/#4176 — flagging only.
- **Standards/QBL mastery gap (Asana #5668 → #4167, #4168, #4176).** The QBL
  (Quality Block/Lesson / power-standard) flag that drives "O3 - Standards
  Mastery", "DKI - Standards Mastery Grid/Bars", and the Region/School/Classroom
  "QBL Mastery" sheets resolves only from a Google Sheet
  (`stg_google_sheets__assessments__qbls_power_standards`) with no intermediate
  or mart model and no Cube exposure. This is very likely the same underlying
  gap those three issues describe — any Cube-connector work on QBL/standards
  mastery should start by reading those issues' diagnostics, not just this
  inventory.
- **Goal differentiation silently excludes Miami.**
  `Grade Goal (Differentiated)`, `School Goal (Differentiated)`, and
  `Region Goal (Differentiated)` all gate their override tiers (fixed 0.8 for ET
  module type; `grade_goal + .1` for CRQ/TP) on
  `region IN ('Camden', 'Newark', 'Paterson')`. Miami always falls to the bare
  `ELSE grade_goal` branch — same underlying mart column
  (`dim_assessment_goals.grade_goal`), different effective target. This is a
  real regional difference in dashboard behavior, not a filter artifact; confirm
  with the DDI/assessments team whether Miami is deliberately held to a flatter
  goal or whether this is a known gap before porting goal logic to Cube.
  `dim_assessment_goals` is listed in `cube.yml`'s
  `cube_semantic_layer.depends_on` but no cube file currently reads it — it's a
  declared-but-unwired dependency.
- **Walkthrough data is a second source entirely.** Everything under
  `response_type = 'walkthrough'` (the LP2 Walkthrough Indicators sheets, the
  walkthrough branch of `Is Mastery Int`) comes from
  `int_performance_management__observation_details` / the
  `fct_staff_observation*` marts, not from the assessment-scores fact the rest
  of the dashboard reads. Those marts exist and are mart-ready but have no Cube
  cube/view yet (a `staff-observations` access tier is scaffolded in
  `access.buildGroups` per `.claude/rules/cube-authoring.md` but unwired).
- **i-Ready lesson-passing measures are ES/MS only by construction** — the HS
  branch of `rpt_tableau__ddi_dashboard.sql` nulls them out explicitly, not a
  display filter. Treat "all regions" as "all regions, ES/MS grades only" for
  this specific measure family.
- Collapsed into the "override/goal-status/goal-distance" rows above: ~10 near-
  identical per-level (Grade/School/Region) and per-source (i-Ready/Walkthrough)
  variants of the same goal-distance-and-status pattern, to stay inside the line
  budget. Same for 4 region-literal `'Camden'/'Miami'/'Newark'/'Paterson'`
  text-concatenation helpers on `LP - Bucket Rosters` — layout only, omitted as
  `workbook-only`/excluded.
- `rpt_tableau__assessment_dashboard.sql` has a structurally separate Paterson
  branch (joins course enrollments on `discipline` instead of
  `illuminate_subject_area`, "temp pending course fixes") — a data-engineering
  seam, not a different regional feature set from the dashboard user's
  perspective, so it isn't broken out as its own row above.

### Notes

- All three upstream rpt_ models (`rpt_tableau__miami_fast`,
  `rpt_tableau__miami_k2_iready`, `rpt_tableau__miami_k2_star`) hard-filter
  `region = 'Miami'` — the region hint is confirmed, not assumed. The two K-2
  models also filter to `grade_level < 3` and the current academic year only (no
  prior-year rows), so iReady/STAR measures above are Miami + K-2 scoped and
  FAST measures are Miami, grades 3+, current + 1 prior year.
- The Asana blockers (`fct_state_assessments`, `fct_iready_diagnostics` don't
  exist) are accurate: there is no dedicated iReady-diagnostic or
  state-assessment fact — both route through the general-purpose
  `fct_assessment_scores_enrollment_scoped` / `student_assessment_scores` cube,
  which covers proficiency rate, scale score, and placement/achievement band
  well, but has NO growth/SGP/gain concept and NO domain/standard-mastery grain
  for any source. That gap (not region or proficiency coverage) is the real
  blocker for a 1:1 Cube swap-in of this dashboard.
- `performance_band_label_number` (the cube's one ordinal-ranking field) is
  hard-coded null for BOTH state (FAST) and vendor (iReady/STAR/DIBELS) branches
  in `fct_assessment_scores_enrollment_scoped.sql` — only internal Illuminate
  rows populate it. This silently defeats any attempt to recreate the FAST
  8-tier sublevel color-sort or STAR/iReady mastery-level ordering purely from
  the existing cube.
- Classified `is_fldoe_growth` / `gr3_retention_flag` / `is_low_25` as
  mart-missing rather than mart-ready because the logic lives inline in the
  `rpt_tableau__miami_fast.sql` extract itself, not in a `models/marts/`
  dim/fact — per the task's mart-ready definition (computed in `marts/`).
- The "pcto:cnt" (percent-of-total) FAST sublevel-distribution bars are a
  Tableau table calc over a cube-coverable count (`count_scored` grouped by
  `proficiency_level`); the percent-of-total arithmetic itself would need to be
  done client-side (Tableau/BI layer), not a missing cube primitive.
- Grouped near-identical per-subject/per-window variants of the same FAST/
  iReady/STAR measure into single rows above (e.g. Region/School/Teacher "KPI -
  FAST Growth" sheets all read the same `is_proficient` field).

### Notes

- **Region finding (verified, contradicts hint)**: the rpt_ model's own WHERE
  clause is `co.region in ('Newark', 'Camden')` — hardcoded to exactly those two
  regions. The workbook still carries a "Region" filter shelf, but it can only
  ever show 2 values. Miami (FL) never appears, and Paterson — a third NJ region
  — is also excluded despite the task hint reading "NJ + FL." Any Cube/mart
  replacement must preserve this narrower scope unless a conversation with
  Academics/Compliance confirms Paterson and Miami should be added.
- **Two orphaned worksheets** (`Accommodations Audit - IEP`,
  `Accommodations Audit - 504`) exist in the .twb, are not `hidden='true'`, but
  are zones on no dashboard and not in the server's published-views list.
  Treated as out of scope (see sheets-excluded line above) rather than
  flagged-include, since "hidden on the server" doesn't quite describe them —
  they appear to be an earlier, superseded draft of the current
  `School - 504/IEP Audit` sheets.
- **7 datasource columns are completely unused** in any of the 17 worksheets:
  `advisor_name`, `team`, `specialed_classification`, `state_studentnumber`,
  `academic_year`, `school_level`, plus the two `asmt_exclude_*` measure fields
  noted above. These are candidates to drop from the rpt_ model's SELECT if no
  other consumer needs them (not verified here — out of scope).
- **No Cube cube or view anywhere in `src/cube/model/` mentions accommodation,
  testing-format, or state-testing-accommodation concepts** — confirmed by a
  case-insensitive grep across cubes and views for
  `accommodation|state_testing`. Every cube-covered row above is "covered" only
  because a DIFFERENT dashboard's cube
  (`student_attendance_enrollment_daily_view`, built for attendance) happens to
  expose the same generic student/grade/ school/region/IEP/ELL dimensions
  through its nested join paths — it was not built with this dashboard's
  population (enrolled-with-accommodation-record) in mind, so querying it for
  this use case means pinning to a date and accepting attendance-record
  population semantics. Flagging this as a judgment call: a reviewer could
  reasonably call these "partial" rather than full cube-covered.
- **No mart-ready rows exist in this inventory.** Every field that is
  accommodation/test-type specific lives only in the rpt_ model's unpivot
  (sourced straight from PowerSchool staging, no intermediate layer); every
  field that's generic enough to already be modeled (grade, school, region, IEP,
  ELL) is already one step further along — cube-covered — rather than sitting at
  mart-ready. This matches the Asana blockers: no `fct_state_assessments` /
  `fct_enrollment` exists yet to carry the accommodation-roster grain, so
  there's no intermediate "mart but not cube" stop for these fields today.
- `dim_students` and `dim_locations` (named in the Asana blockers as
  not-yet-existing) **do already exist** in
  `src/dbt/kipptaf/models/marts/dimensions/`. Only `fct_state_assessments` and
  `fct_enrollment` are confirmed genuinely absent (`find`/`grep` across
  `models/marts` returned nothing for either name).
