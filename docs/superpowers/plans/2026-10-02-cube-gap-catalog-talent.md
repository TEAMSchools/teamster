- upstream datasources (all embedded, none "published"/shared):
  `rpt_tableau__smartrecruiters`, `rpt_tableau__seat_tracker_snapshot`,
  `demo_calendar (recruitment_projections)`
- rpt_/source models in use: `rpt_tableau__smartrecruiters` (application
  funnel), `rpt_tableau__seat_tracker_snapshot` (weekly seat/staffing snapshot).
  `demo_calendar (recruitment_projections)` has **no dbt model** — it is a
  non-warehouse embedded datasource (calendar/meeting export). Asana's task also
  names `rpt_tableau__seat_tracker` (non-snapshot) as being replaced, but it is
  not an upstream datasource of this workbook — only the snapshot version is
  embedded here.
- published dashboards inventoried (9): App Progress Report, App Stats, Battle
  Board, Interview/Demo Tracking, Launchpad, Leading Indicators, Quality App
  Conversions, Stalled Applications Report, Timeline
- excluded: `Home` and `Battle Board_live` are navigation/duplicate dashboards
  (button-only, zero worksheet zones) — not inventoried as content. All 47 real
  worksheets in the workbook are used on one of the 9 content dashboards; 46
  show `hidden='true'` window state, which is normal Tableau behavior for sheets
  embedded only in dashboards, not orphaned scratch sheets — 0 orphans found.
- regions served by this dashboard overall: **Newark, Camden, Miami only.** The
  string "Paterson" does not appear anywhere in the workbook except once,
  inertly, inside a generic/reused color palette (`<bucket>"Paterson"</bucket>`
  mapped to a color never applied to any field actually in use). The
  `Job City (group)` bin used throughout the SmartRecruiters-backed sheets only
  names "Camden + Newark" and leaves Newark/Camden/Miami as raw passthrough
  values — no 4th region. Seat-tracker sheets (`entity`, `short_name`,
  `grade_band`) carry no explicit member list in the workbook to confirm
  Paterson's absence independently, but the network-wide text search found
  nothing — treat as **not served** pending confirmation against live ADP/
  SmartRecruiters region config. This contradicts the "network-wide" hint.

### Notes

- **No talent/recruiting Cube exists.** Confirmed by grepping
  `src/cube/model/cubes/**` and `views/**` for
  `recruit|candidate|seat| staffing|job_posting|hire` — the only hits are
  `staff.original_hire_date` / `rehire_date` on the current-staff cube, which
  describe an already-hired employee, not the candidate pipeline. Every row
  above is therefore `mart-ready` or `mart-missing`; there are zero
  `cube-covered` rows to report.
- Asana's blocker list (`fct_staff_seats`, `fct_teammate_applications`,
  `dim_adp_positions`) does not exist in the marts tree yet — confirmed absent
  via `find`. The marts that DO exist (`fct_job_candidate_applications`,
  `dim_job_candidates`, `dim_job_postings`, `dim_staffing_positions`,
  `dim_locations`) cover most of the SmartRecruiters-funnel and seat-tracker
  numbers surprisingly well as `mart-ready` — the real gap is (a) the
  multi-branch "reviewed within 7 days" SLA business rule, (b) a modeled
  Recruiter entity, and (c) `entity`/`grade_band` not yet carried onto
  `dim_staffing_positions`.
- Grouped 14 near-identical Quality-App-Conversions worksheets (`3s`/`4s`/`3+4s`
  × `Demoed`/`Offered`/`Phoned`/`Hired`) into one measures row — they differ
  only by a resume-score-bucket filter and funnel stage, all driven by the same
  per-application "reached stage X" LOD pattern.
- Excluded as pure formatting/navigation, not metrics: `Home` and
  `Battle Board_live` dashboards (button-only pages with zero worksheet zones);
  the `shape`-only "Met Weekly Goal" icon encoding (same field as the
  Reviewed/Total measure); `[Multiple Values]` / `[:Measure Names]` /
  `[Action (...)]` pseudo-fields seen on every BAN/KPI-tile worksheet and every
  dashboard filter action — these are Tableau shelf/action mechanics, not
  workbook fields, and were resolved by reading each worksheet's `Measure Names`
  filter member list directly from the XML.
- `Unreviewed Applications` (Launchpad), `Did Not Meet Goal` (App Progress
  Report), and `Stalled Applications` (Stalled Applications Report) are
  operational drill-through worklists (one row per application, URL + tooltip
  recruiter) rather than aggregated metrics — their underlying flags are already
  captured by the Percent Stalled / Weeks-Meeting-Goal measure rows above.
- Region finding is the most consequential surprise here: despite the task hint
  ("staff recruitment network-wide"), nothing in this workbook evidences
  Paterson — recommend confirming with the Recruitment team whether Paterson
  recruiting genuinely runs through a separate process/tool before scoping a
  Cube build to "all 4 regions."
