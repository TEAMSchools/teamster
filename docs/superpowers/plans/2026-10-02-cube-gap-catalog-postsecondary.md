### Cube coverage: none

No cube or view under `src/cube/model/` reads `dim_colleges` or
`dim_college_enrollments`, and there is no postsecondary/alumni domain at all in
Cube (only `conformed`, `courses`, `staff`, `student_assessments`, `students`).
`src/dbt/kipptaf/models/exposures/cube.yml` lists both marts under
`cube_semantic_layer.depends_on` (lines 17-18), but that is either aspirational
or stale — no `sql:` in any cube/view file actually points at them. **Every
measure and dimension below is therefore `cube-covered: none`** — the
classification question is only mart-ready vs. mart-missing. I've dropped the
`cube-covered` possibility from the status column narrative below and only call
it out where relevant.

Per the Asana task: `fct_postsecondary_enrollment`, `fct_alumni_contact_notes`,
`fct_survey_kfwd`, `dim_alumni`, `dim_institutions` — confirmed **absent** (no
matching file anywhere under `src/dbt/kipptaf/models`). `dim_colleges` and
`dim_college_enrollments` **do exist** and cover a meaningful slice: college
identity/selectivity/HBCU status (`dim_colleges`) and NSC enrollment
status/degree/major/class-level (`dim_college_enrollments`) — see mart-ready
rows below.

### Notes

- **Biggest finding**: there is no postsecondary/alumni Cube domain at all, so
  this workbook's entire measure set is mart-missing or workbook-only — there
  are zero cube-covered rows. The Asana task's blocker list is accurate; the gap
  is total, not partial.
- `dim_colleges` and `dim_college_enrollments` are real, usable building blocks
  today for the college-identity and raw-NSC-status slice (HBCU flag,
  selectivity, state, degree/class-level/graduated/withdrawn), but they cover
  maybe 10-15% of this workbook's measure surface. The other ~85% (advising
  touchpoints, application/acceptance/matriculation tracking, ECC-window grad
  rates, financial aid, career-readiness survey, re-enrollment) has no dbt mart
  today — it all lives as bespoke SQL inside the 7 `rpt_tableau__kfwd_*` / 1
  `rpt_gsheets__kfwd_*` extracts.
- Region scope is a correction to the task's hint: the workbook is **not**
  NJ-only. `rpt_tableau__kfwd_dashboard.sql` has no region `where` clause and
  explicitly carves out KIPP Miami contacts; treat Miami as in-scope for any
  migration plan, not "possibly."
- `cube.yml`'s `cube_semantic_layer.depends_on` lists `dim_colleges` and
  `dim_college_enrollments` even though no cube/view reads them — flag this to
  whoever owns that exposure file; it's either a forward-declared TODO or drift.
- Grouping judgment calls: the "As1-As24 / cc1-cc5" family, the "Is Xyr [deg]
  Grad Int" family, and the Match- Applications/Placement application-outcome
  family are each 15-45 near-identical per-cohort-window or per-degree-type
  variants of one underlying metric shape; I collapsed each into one row rather
  than listing every variant, per the grouping instruction.
- Excluded as pure display/layout: `MIN`/`MAX(1)` placeholders, `index()` sort
  keys, `View By - *` parameters, string-literal "Title" labels, and the
  `COUNT(...)/20` and `COUNT(...)/40` goal-denominator helpers on Re-Enrollment
  (these ARE workbook-only despite being numeric — they're fixed constants used
  only to compute a bar-chart percent-of-goal, not a standalone metric).
- `rpt_tableau__kfwd_career_launch_survey_weights` is a sibling extract in dbt's
  `kfwd_` family but is not wired into this workbook (not in
  `upstreamDatasources`) — don't assume it needs migrating alongside this
  dashboard.
