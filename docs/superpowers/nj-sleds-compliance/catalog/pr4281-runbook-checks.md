Runbook") and `2026-06-29-nj-sleds-course-roster-runbook-design.md` (346 lines,

## 2. Data model the runbook assumes

### Where the data comes from

- Native PowerSchool extracts (copied to stable filenames, no prep script): per
  region, `NJ_Staff_Course_Submission <Region>.csv` and
  `NJ_Student_Course_Submission <Region>.csv` (lines 171-173, 217-220).
- NJ SLEDS portal exports (pulled by compliance / the state-access staff, since
  the intern has no state-system access; runbook line 1870, spec:32-34):
  - "Export- Staff Management Submission Newark.csv" and "...Camden.csv" ->
    `ref_state_staff_<region>` (lines 146-156; spec:128-140: 85 columns, about
    1,053 staff, projected to 24 columns, SSN dropped).
  - "Export- State Student Record Newark.csv" and "...Camden.csv" ->
    `ref_state_student_<region>` (lines 158-168; spec:129: about 100 columns,
    projected to 5).
  - Loading is conditional: "also load the state Staff Management / SMID export
    if compliance can provide it" (lines 103-104, 1883).
- SCED list: `NJSLEDS_SCED-Course-Codes.xlsx` (prior-to-secondary and secondary
  sheets, about 2,060 rows) -> `ref_sced_codes` via `build_ref_sced_codes.py`
  (lines 139-144, 177-178). The runbook does not state where the workbook is
  obtained or whether it is a portal download or a public file. It links the
  NCES SCED manual (line 759) as a lookup.
- Public NJDOE files loaded as tables: none. The NJDOE school directory
  (line 700) is named only as a manual lookup for correct CDS values; the
  NJSLEDS OPE ID List (line 1772-1777) is named as not loaded.
- CDS values: two literal combinations inlined in SQL, no reference table
  (spec:152-163). Newark County 80, District 7325, School 965. Camden County 07,
  District 1799, School 111.
- PowerSchool warehouse models read by the setup queries (not `cokafor`):
  `kipptaf_powerschool.int_powerschool__teachers` (`teachernumber`,
  `homeschoolid`, `_dbt_source_relation`) and
  `kippnewark_powerschool.stg_powerschool__schools` /
  `kippcamden_powerschool.stg_powerschool__schools` (`school_number`,
  `alternate_school_number`, `countynbr`, `state_excludefromreporting`).
  `S_NJ_SEC_X` is not staged in the warehouse (spec:238-240; runbook 1470-1472).

### Load shape

- Project `teamster-332318`, dataset `cokafor` (spec:56-59). Loaded with
  `bq load --source_format=CSV --skip_leading_rows=1 --replace` and explicit
  STRING schemas; `--autodetect` is prohibited because it strips zero padding
  from `subject_area`, `course_identifier`, and CDS values (lines 204-209).
  `--replace` per region base table; `--noreplace` appending is rejected (lines
  186-193). Leading-zero check at lines 364-373.
- Each region is a separate PowerSchool instance, so each extract and state
  export arrives as two CSVs.

### Union views (lines 300-338)

`create or replace view` of `select *, '<region>' as region` from the Newark
base table `union all` the Camden base table, giving: `stg_staff_extract`,
`stg_student_extract`, `ref_state_staff`, `ref_state_student`. `region` is
`'newark'` or `'camden'`. `ref_sced_codes` has no view. All checks query the
view names. Joins within region: checks 2, 3, 12, 14, 15, 16 join on the local
key plus `region` (lines 195-202); checks 1, 4-11, 13 are per-row and carry
`region` for routing. Stated reason: local IDs repeat across regions (fewer than
10 shared staff LSIDs and 33 shared student local IDs in the EOY data).

Prep scripts (lines 127-169): `build_ref_sced_codes.py` (needs openpyxl),
`build_ref_state_staff.py` (drops SSN), `build_ref_state_student.py`, under
`docs/superpowers/nj-sleds-roster/setup/`.

## 3. Cleaning model and PII rules (5 lines)

1. Source-fix only: every defect is fixed in PowerSchool (SCED codes in
   `S_NJ_CRS_X` / `S_NJ_SEC_X`, staff state-ID overrides and SMID in
   `S_NJ_USR_X`, orphan section cleanup); no rewriting or post-filtering of
   extract CSVs in BigQuery (lines 42-45, 98-115, 1134-1138).
2. Handoff artifact is the regenerated native extract; the loop is re-extract,
   re-load, re-run (typically 2-4 loops); state-side items (new SMIDs, name/DOB
   pushes into Staff Management / state SIS) go to the compliance handoff sheet.
3. Row-level worklists with names, DOBs, and IDs stay in BigQuery `cokafor` and
   in-tenant Google Sheets; never copied to the cowork project, chat, a commit,
   or any external surface (lines 79-82).
4. The cowork project gets rules, categories, counts, and de-identified samples
   only; the check-17 rollup is the only artifact from the runbook that goes
   there; state error reports are PII and are triaged row-level in BigQuery/VS
   Code, with only the de-identified taxonomy shared (lines 83-89, 1927-1935).
5. `SocialSecurityNumber` is never loaded (dropped by
   `build_ref_state_staff.py`; masked in the export anyway); worklist tabs
   exclude `FirstName`, `LastName`, `DateOfBirth`, and SID, using
   `LocalStaffIdentifier`, `LocalIdentificationNumber`, `StaffMemberIdentifier`,
   `LocalSectionCode` as locators (lines 90-94, 1798-1801).

## 4. Setup-level fixes described

- School Setup CDS fields (lines 1418-1472): PowerSchool -> School Setup ->
  State Information, per reporting school. `SchoolCodeAssigned` comes from the
  school's Alternate School Number (`alternate_school_number`; falls back to the
  internal school number when unset, the source of `732`); `CountyCodeAssigned`
  from the school County code (`countynbr`); `DistrictCodeAssigned` from a
  district-level state setting, already correct (7325 / 1799). Set Alternate
  School Number to 965 (Newark) or 111 (Camden) and County to 80 or 07. Caveat
  stated: the mapping was inferred from data; confirm against NJ State Reporting
  setup; `S_NJ_SEC_X` section overrides are a possible second input (lines
  1467-1472). The spec records a conflicting earlier hypothesis: warehouse shows
  every Newark school with `alternate_school_number = 965`, so the Alternate
  School Number fallback was "ruled out" there (spec:233-238; runbook 727-732,
  1077, 1120). The runbook's later setup section (line 1433, 1462-1465) says
  Alternate School Number unset is the cause.
- Staff state-ID override fields and SMID entry (lines 479-526, 1514-1622): LSID
  override in `S_NJ_USR_X` from `njsleds_lsid`; first/last name overrides
  entered where PowerSchool differs from NJ SLEDS; SMID entry; upload rows carry
  `homeschoolid` with `schoolid` identical to avoid duplicate user records; rows
  with blank `homeschoolid` are excluded and resolved by hand (1516-1522,
  1618-1620).
- State SID population (lines 1481-1512): enter `njsleds_sid` on the student's
  State/Province - NJ page in PowerSchool.
- Course SCED overrides (lines 1690-1700): Course Submission Information panel
  override dropdowns, stored in `S_NJ_CRS_X`; each is a true override ("if
  blank, this course value will be used").
- Section exclusion (lines 1157-1163): "Exclude from Course Roster Reports" on
  the Course Submission Information panel, stored in `S_NJ_SEC_X`.
