# Existing dbt tests relevant to NJ state submissions

Inventory by an Explore subagent, 2026-10-20 evening. Facts from yml and
singular-test SQL; dbt was not run, so "effective severity" is derived from yml
plus `dbt_project.yml`. No student data.

Abbreviations: PS = `src/dbt/powerschool/models/sis`; KT =
`src/dbt/kipptaf/models`.

Defaults: kipptaf and the three NJ districts default to `warn`
(`+severity: warn`); the powerschool package declares none, so it resolves to
dbt's own `error`.

## Headline

No test anywhere checks: SID presence or format; county, district, school or
municipal codes; race/ethnicity; birth city/state/country; grade-level domain on
NJ student models; entry/exit codes; Title I, migrant, 504, FRL domain on NJ;
SCED codes; course credit; grades earned (`storedgrades`); staff state ids or
roles; assessment registration or accommodations.

The only NJ-submission-relevant coverage is structural: uniqueness, a few
enrollment-date, span-overlap and section-coverage checks, and two enum tests.

## 4. Conventions

- 1,701 tests across yml; config keys used: `severity` (1,006), `meta` (82),
  `where` (62), `enabled` (29), `store_failures` (1), `warn_if` (1).
- Only test-level `meta` key is `meta.dagster.ref`
  (`config.meta.dagster.ref.name`, plus `package:` for source-package tests). No
  `runbook`, `owner`, `submission`, or similar key exists anywhere.
- kipptaf `dbt_project.yml:22-25`: `+severity: warn`, `+store_failures: true`,
  `+store_failures_as: view`. Districts same, scoped under their own name.
  Powerschool package: no project-level config → `error`.
- `.claude/rules/dbt-yaml.md:262-310`: staging tests MUST set `severity: error`
  explicitly; a test re-runs only when its host model materializes, and views do
  not re-materialize on data change, so a check on a view goes dormant;
  `accepted_values` passes NULLs (pair with `not_null`); `expression_is_true`
  cannot use window functions; FK checks are column `relationships` tests on the
  pre-join model; single-column tests on the column, multi-column in a
  model-level block.
- `.claude/rules/dbt-models.md:157-178`: every stg/int/rpt/dim/fct needs a
  uniqueness test; union views and thin district wrappers are excepted.
- `standard-baseline.tsv` tracks A1/A8 layer violations, NOT tests. Submission
  models listed as A1 edges (#5809-#5812): `rpt_gsheets__nj_state_test_roster`,
  `rpt_tableau__state_testing_accomodations`,
  `rpt_powerschool__autocomm_students*`, `rpt_powerschool__autocomm_teachers`,
  `dim_student_iep_status`.
- Stored failures are views; failure rows for student models are PII
  (`.claude/rules/ferpa-pii.md:170`).
